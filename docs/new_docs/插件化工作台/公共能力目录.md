## 通用规则

- 所有 HostService 方法必须标注 `@RequiresCapability` 且首参为 `InvocationContext`。
- 插件获取的服务实例为 JDK 动态代理，每次调用均校验能力授权与 pluginId 匹配。
- 能力码以宿主数据库 `sys_plugin_capability` 表为准，不信任插件自身声明。
- 未声明能力或缺少注解的方法在注册阶段即被拒绝（fail closed）。
- 插件缓存代理实例后，能力撤销会在下一次调用时被数据库校验拦截。

### 事件专项能力码

订阅总开关 `EVENT_SUBSCRIBE` 与事件专项能力需同时满足。撤销专项能力后分发立即拒绝。

| 事件类型 | 专项能力码 |
|----------|-----------|
| WORKFLOW_APPROVED | `EVENT_SUBSCRIBE_WORKFLOW_APPROVED` |
| WORKFLOW_REJECTED | `EVENT_SUBSCRIBE_WORKFLOW_REJECTED` |
| EMPLOYEE_HIRED | `EVENT_SUBSCRIBE_EMPLOYEE_HIRED` |
| EMPLOYEE_LEFT | `EVENT_SUBSCRIBE_EMPLOYEE_LEFT` |
| FILE_UPLOADED | `EVENT_SUBSCRIBE_FILE_UPLOADED` |
| ATTENDANCE_EXCEPTION | `EVENT_SUBSCRIBE_ATTENDANCE_EXCEPTION` |

> `unsubscribe` 仅依赖总开关 `EVENT_SUBSCRIBE`，允许仍有 API 权限的插件清理订阅。代理层与 `DefaultEventService` 实现层均检查总开关；后续分发器必须逐次重查事件专项能力。

## 事件类型

| 事件 | 触发时机 |
|------|----------|
| WORKFLOW_APPROVED | 审批通过 |
| WORKFLOW_REJECTED | 审批驳回 |
| EMPLOYEE_HIRED | 员工入职 |
| EMPLOYEE_LEFT | 员工离职 |
| FILE_UPLOADED | 文件上传完成 |
| ATTENDANCE_EXCEPTION | 考勤异常 |

> 六类 v1 payload schema 见 [plugin-sdk契约.md](./plugin-sdk契约.md#v1-payload-schema)。同步分发阶段逐次重查总开关与事件专项能力。
