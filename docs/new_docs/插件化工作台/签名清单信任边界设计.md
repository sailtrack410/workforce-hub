# 插件签名清单信任边界设计

## 目标

安装和启动恢复只能信任已签名 JAR 内的 `plugin.json` 来决定插件类型、发布方和前端产物摘要，禁止安装请求中的外部 metadata 改写这些字段。

## v0.1 清单契约

```json
{
  "id": "hello-plugin",
  "version": "0.1.0",
  "sdkVersion": "0.1.0",
  "minHostVersion": "0.1.0",
  "maxHostVersion": "0.2.0",
  "javaVersion": "17",
  "type": "UI",
  "provider": "Workforce Hub",
  "frontendSha384": "sha384-c527zMMh7jwa0gTNl9fI1Mg5xEqGXyEFnTFCcjr7fokaoyPHzkIY7kC9f13c4zUQ"
}
```

| 字段 | 规则 |
|------|------|
| `type` | 必填，只允许 `UI` 或 `FUNCTIONAL` |
| `provider` | 必填，必须是非空字符串 |
| `frontendSha384` | `UI` 必填，格式必须是单个 `sha384-` 加 64 位 Base64；`FUNCTIONAL` 禁止声明 |

`frontendEntry` 不进入签名清单。宿主始终根据已签名的插件 ID 生成 `/plugins/{pluginId}/index.js`，不接受上传方提供任意脚本路径。

## 数据流

1. 宿主先把上传 JAR 复制到 `pluginsRoot/.snapshots` 并完成 RSA 验签。
2. `PluginVersionService` 从该快照中唯一的 `plugin.json` 解析身份、版本、`type`、`provider` 和 `frontendSha384`。
3. `PluginManagerService.install` 只从解析结果写入 `sys_plugin.type/provider/frontend_sha384`，并按插件 ID 派生 `frontend_entry`。
4. 安装请求中的同名 metadata 字段全部忽略；`signerId` 和分离签名仍由安装请求提供并由宿主校验。
5. 同 ID 替换时，新包 `signerId` 必须与旧 `UNINSTALLED` 记录一致；其他可信签名者也不能接管旧插件 ID 及其保留配置和授权。
6. `restorePlugins()` 重新验签、重新解析清单，并要求数据库中的身份、版本、类型、发布方、前端入口和 SRI 与清单派生值一致；不一致则标记 `ERROR`，禁止加载。
7. 员工清单仅返回 `ACTIVE + UI` 且 SRI 合法的插件，前端加载器继续固定使用 `/plugins/{id}/index.js`。

## 兼容性与边界

- 不提供外部 metadata 回退。旧插件 JAR 缺少新字段时安装或恢复失败，必须重新构建并签名。
- 现有 `sys_plugin` 已具备所需列，不新增 Flyway 迁移。
- `name` 和 `description` 本次仍是安装展示信息，不参与代码执行授权；后续若作为可信品牌信息展示，再纳入签名清单。
- `provider` 是已签名声明，不等于证书主体；真正的签名者身份仍以宿主可信公钥白名单中的 `signerId` 为准。
- 前端摘要绑定的是独立交付的 IIFE `index.js`。发布顺序必须是：构建 IIFE → 计算 SHA-384 → 写入 `plugin.json` → 打包 JAR → 对完整 JAR 签名。

## 错误处理

- 缺失、空值、错误类型、未知 `type`、非法 SRI 或类型与 SRI 组合冲突均在 PF4J 加载和 Flyway 迁移前拒绝。
- 安装失败继续沿用现有快照与 PF4J 清理语义。
- 恢复时字段不一致统一使用“插件清单与安装记录不一致”，不向员工端暴露内部字段差异。

## 测试要求

- `PluginVersionServiceTest` 覆盖 UI/FUNCTIONAL 合法清单及字段缺失、非法类型、非法 SRI、组合冲突。
- `PluginManagerSignatureSafetyTest` 覆盖外部 metadata 无法覆盖签名字段，以及恢复时类型、发布方、入口和 SRI 漂移被拒绝。
- `PluginManagerServiceIntegrationTest` 从版本控制中的 hello-plugin 源码和 `plugin.json` 构建并签名真实 UI JAR，验证四字段持久化及四类单字段漂移在 PF4J 加载前 fail closed。
- `plugin-iife-build.test.ts` 构建 hello-plugin IIFE，计算真实 SHA-384，并断言与 `plugin.json` 一致。
- 最终运行后端完整 reactor 测试、employee-web 全量测试与构建、`git diff --check`。
