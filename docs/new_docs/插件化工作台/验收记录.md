## 当前限制

在新建、仅完成宿主 Flyway 迁移的数据库首次启动时，默认 Flowable 配置仍有两个已知阻断：

1. V11 未创建 Flowable IDM 的 `ACT_ID_*` 表；启用 `FLOWABLE_DB_SCHEMA_UPDATE=true` 后，自动升级在缺少 `ACT_ID_USER` 处失败。
2. 临时关闭 IDM/EventRegistry 后，fat JAR 自动部署 BPMN 时，嵌套 JAR URL 下 `BPMN20.xsd` 的相对 include 无法解析。

首次升级失败可能在隔离库中留下部分 Flowable 版本状态；后续复验应重建该隔离库，不能把失败后的库当作干净启动基线。

因此本轮只证明插件链路在隔离、明确的临时启动条件下可运行，不声称默认配置或 Docker Compose 已经通过。第 7 周的 100 次启停、真实事件端到端发布点、CSP、重启恢复、关闭超时、ClassLoader 泄漏和内存增长监控仍按《开发计划》保持未完成。

另外，宿主 `SecurityConfig` 当前全局 `csrf.disable`；本轮仅通过自动化测试验证当前动作 `POST` 网关的 `Origin`/`Referer` 白名单校验，浏览器链路未验证该校验。全站 Spring CSRF、其他 Session 写接口及未来管理 API 仍未覆盖，非本地部署还必须显式设置 `WORKFORCE_PLUGIN_GATEWAY_CSRF_ALLOWED_ORIGINS`。
