# 插件化工作台 - 风险与约束

## 风险清单

| 风险                     | 应对方案                                                       |
|--------------------------|----------------------------------------------------------------|
| PF4J与Spring Boot3.x兼容 | 用PF4J Core 3.15.0，手动管理Spring子Context                    |
| 安全风险                 | JAR签名、SHA-256、大小限制、路径校验、临时隔离区               |
| 前端动态加载             | Host SDK方案，宿主暴露Vue运行时                                |
| 跨插件事务               | 共享数据库，SPI接口调用，通用调用网关                          |
| ClassLoader冲突          | PF4J自带隔离机制，每个插件独立ClassLoader                      |
| Flyway版本冲突           | 每个插件独立history表，迁移失败禁止启动                        |
| 员工端权限               | 后端过滤，先支持"全部/主管/部门/岗位/指定用户"                 |

## PoC 阻断项（第1周必须解决）

| 问题                     | 为什么阻断                                                     |
|--------------------------|----------------------------------------------------------------|
| window.Vue 不存在        | Vite构建的应用不会自动暴露全局变量，插件IIFE加载会报错         |
| 插件资源没有部署路径     | Nginx没有 /plugins/ 路由，server-storage 未挂载到 web 容器     |
| ClassLoader 无法释放     | 停用插件后线程、ThreadLocal、JDBC驱动、Spring Context 泄漏     |

## 遗留设计问题（后续阶段补齐）

### 升级与回滚
- 升级API、同插件多版本处理、降级限制
- 旧产物保留、失败回滚策略
- 数据库迁移通常只能前进，不能承诺完整回滚

### 生命周期并发
- 启停锁、重复请求幂等
- 运行中请求排空、停止超时
- 依赖插件逆序停用
- 服务崩溃后的中间状态恢复

### 依赖契约
- 版本范围、循环依赖检测
- 拓扑启动、反向依赖卸载限制

### 宿主兼容性
- plugin.json 缺少 sdkVersion、minHostVersion
- Java版本和前端协议版本约束

### 通用调用网关
- URL、动作注册、请求/响应结构
- 参数校验、逐动作权限、事务边界、超时及统一错误码

### CSRF防护
- 插件上传、启停、配置等高权限接口需要严格校验 Origin/Referer
- 或单独恢复 CSRF Token

### 配置安全
- 类型、默认值、校验、敏感字段脱敏
- 密钥引用和"修改后需重启"标记

### 签名信任链
- 可信证书/公钥来源、签名者白名单
- 轮换、吊销、过期处理和禁止旧版本回放

### 前端隔离与卸载
- CSS 命名空间、样式清理、事件监听清理
- 错误边界、插件停用后的路由回退

### 缓存策略
- 内容哈希URL、不可变缓存和清单禁缓存
- 避免新旧代码混用

### 部署链路
- Nginx 添加 /plugins/ 路由
- web 容器挂载 server-storage

### ClassLoader释放
- 线程、线程池、ThreadLocal、JDBC驱动、文件句柄
- 日志组件和 Spring Context 的关闭协议及泄漏检测

### 可观测性
- 插件健康状态、启动耗时、调用量、错误率
- 活动请求数、最后失败原因、独立日志和告警指标

### 验收量化
- 启停次数、允许的内存增长、停止超时、加载耗时
- 最大包大小、故障恢复时间及权限测试矩阵
