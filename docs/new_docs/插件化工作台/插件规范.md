# 插件化工作台 - 插件规范

## plugin.json 规范

### 当前 v0.1 运行时字段

`plugin.json` 必须是 JAR 根目录中唯一的同名文件，最大 64KB。当前宿主读取以下版本、身份与签名运行时字段：

```json
{
  "id": "hello-plugin",
  "version": "0.1.0",
  "sdkVersion": "0.1.0",
  "minHostVersion": "0.1.0",
  "maxHostVersion": "0.2.0",
  "javaVersion": "17",
  "type": "UI",
  "provider": "Workforce Hub",
  "frontendSha384": "sha384-c527zMMh7jwa0gTNl9fI1Mg5xEqGXyEFnTFCcjr7fokaoyPHzkIY7kC9f13c4zUQ"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 插件 ID；必须匹配 `^[a-z0-9-]{1,64}$`，并与 `plugin.properties` 的 `plugin.id` 及 PF4J 加载结果一致 |
| version | string | 是 | 严格 `major.minor.patch`；必须与 `plugin.properties` 的 `plugin.version` 一致 |
| sdkVersion | string | 是 | 依赖的 SDK 版本，严格 `major.minor.patch` |
| minHostVersion | string | 是 | 最低宿主版本，严格 `major.minor.patch` |
| maxHostVersion | string | 否 | 最高宿主版本，闭区间上界 |
| javaVersion | string | 是 | Java feature version 的正整数字符串，例如 `17` |
| type | string | 是 | 只允许 `UI` 或 `FUNCTIONAL` |
| provider | string | 是 | 非空发布方声明；不等于真实签名者身份 |
| frontendSha384 | string | 条件必填 | `UI` 必须为 `sha384-` 加 64 位 `[A-Za-z0-9+/]`；`FUNCTIONAL` 禁止声明，包括 `null` |

解析时拒绝重复 JSON 字段、尾随第二个 JSON 值、空字段、错误类型以及 `type` 与 `frontendSha384` 组合冲突。当前未列出的字段会被忽略，不能作为授权、前端加载或其他安全决策的依据。

### 其他展示与规划字段

| 字段 | 规划用途 | 当前状态 |
|------|----------|----------|
| name、description | 展示信息 | 仍来自外部 metadata，不参与代码执行授权 |
| frontendProtocol | 前端协议兼容性 | 未解析、未校验 |
| dependencies | 插件依赖范围 | 未解析，依赖拓扑未实现 |
| capabilities、visibility | 能力申请和可见范围 | 当前以宿主数据库为准，不从 `plugin.json` 自动授予 |
| actions | 动作发现文档 | 当前以 `PluginActionHandler.getDescriptor()` 为准 |
| frontendEntry | 前端入口 | 不进入签名清单；宿主按已签名插件 ID 固定派生 `/plugins/{pluginId}/index.js` |

`name`、`description` 仍是外部展示 metadata；其余规划字段只有在宿主从已签名清单解析、校验并持久化后，才能成为可信配置。`signature` 不属于 `plugin.json` 字段，见“JAR 分离签名要求”。

## 最终安装记录预检

宿主完成验签和 `plugin.json` 校验后，会先构建最终 `PluginRow`，再按数据库列限制做前置校验：

| 字段 | 来源 | 上限 |
|------|------|------|
| pluginId | 已签名 `plugin.json` | 64 字符 |
| name | 外部 metadata；缺省为 pluginId | 128 字符 |
| description | 外部 metadata | 512 字符 |
| type | 已签名 `plugin.json` | 32 字符 |
| jarPath | 宿主快照路径 | 512 字符 |
| jarSha256 | 宿主计算 | 64 字符 |
| signerId | 外部提交并由可信签名者白名单校验 | 128 字符 |
| frontendEntry | 宿主按已签名 pluginId 固定派生；`FUNCTIONAL` 为空 | 512 字符 |
| frontendSha384 | 已签名 `plugin.json`；`FUNCTIONAL` 为空 | 96 字符 |
| provider | 已签名 `plugin.json` | 128 字符 |
| signature | 外部分离签名原始字节 | 65535 字节 |

字段超限或检查时已存在同一插件 ID，会在 PF4J 加载和 Flyway 迁移前拒绝并删除未持久化快照。存在性检查不区分插件状态，`UNINSTALLED` 记录也会阻止同 ID 重装；该检查只减少确定性失败，不提供重装语义或多实例并发安装的原子保证。

`type`、`provider`、`frontendSha384` 不做外部 metadata 回退。旧 JAR 缺少这些字段时必须重新构建并对完整 JAR 签名。

## JAR 包规范

### 必需文件

```
plugin.properties        # JAR 根目录，PF4J 描述文件
plugin.json              # JAR 根目录，v0.1 签名版本清单
com/...                  # 插件编译类
META-INF/extensions.idx  # PF4J 扩展索引（存在扩展时）
db/migration/*.sql       # 可选；不存在时宿主跳过迁移
```

`plugin.properties` 至少提供 PF4J 所需的插件 ID、主类和版本，例如：

```properties
plugin.id=hello-plugin
plugin.class=com.workforcehub.plugin.hello.HelloPlugin
plugin.version=0.1.0
```

`plugin.id`、`plugin.version` 必须与 `plugin.json` 一致。后端 JAR 不包含 `frontend/index.js`；UI 插件前端单独构建为 IIFE `index.js`，部署到 `/plugins/{pluginId}/index.js`，由员工端加载器使用 SRI 校验。发布顺序固定为：构建 IIFE → 计算 SHA-384 → 写入 `plugin.json` → 打包 JAR → 对完整 JAR 签名。hello-plugin 当前真实摘要为 `sha384-c527zMMh7jwa0gTNl9fI1Mg5xEqGXyEFnTFCcjr7fokaoyPHzkIY7kC9f13c4zUQ`。

### 尚未完成的包安全边界

- JAR 总大小、entry 数量和单 entry 大小尚无统一上限。
- 迁移脚本提取尚无总解压大小和文件数量上限，不能宣称已防压缩炸弹。
- 当前只强制 `plugin.json` 唯一，尚未拒绝所有重复 JAR 条目。
- 迁移 SQL 语句白名单尚未实现，不能把文档中的 SQL 类型列表视为运行时校验。
- 安装开始时宿主把源 JAR 复制到 `pluginsRoot/.snapshots`，验签、版本、PF4J、Flyway 和注册表均使用同一快照；安装失败且 PF4J 确认清理成功后删除，清理失败时保留，成功安装后保留供恢复。
- 快照不是内容寻址且没有额外不可变保护；同一 OS 账号可修改快照，恢复阶段验签后的再次打开仍有 TOCTOU 边界。

### JAR 分离签名要求

- JAR、签名和 `signerId` 分离提交；签名不写入 `plugin.json`，也不写入被签 JAR
- 签名输入为 `plugin.jar` 的完整原始字节，算法固定为 `SHA256withRSA`
- `signerId` 必须命中宿主可信公钥白名单，RSA 公钥不少于 2048 位
- `jar_sha256` 只能由宿主计算，禁止信任上传方提交的摘要
- 安装前和服务重启恢复时都必须复验签名与已持久化摘要
- 可信公钥配置在应用启动时读取；新增、轮换或删除签名者都需要重启后生效

## 版本号规范

使用语义化版本：`主版本.次版本.补丁版本`

- 主版本：不兼容的API变更
- 次版本：向后兼容的功能新增
- 补丁版本：向后兼容的问题修复

当前示例：插件版本 `0.1.0`、SDK 版本 `0.1.0`、最高宿主版本 `0.2.0`。

当前校验规则要求插件 SDK 不高于宿主 SDK。宿主 SDK 为 `1.x` 及以上时要求主版本相同；宿主 SDK 为 `0.x` 时还要求次版本相同，例如宿主 `0.1.1` 可接受插件 `0.1.0`，但拒绝 `0.2.0`。
