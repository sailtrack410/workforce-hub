# 插件化工作台 - 数据库设计

以下“已创建”表以 Flyway `V52`、`V54`、`V55`、`V57` 为准。表存在不代表对应管理 API 或完整业务流程已经实现。

## 插件注册表

```sql
CREATE TABLE sys_plugin (
    plugin_id         VARCHAR(64)  PRIMARY KEY,
    name              VARCHAR(128) NOT NULL,
    description       VARCHAR(512),
    version           VARCHAR(32)  NOT NULL,
    sdk_version       VARCHAR(32)  NOT NULL DEFAULT '1.0.0', -- SDK版本
    min_host_version  VARCHAR(32),                 -- 最低宿主版本
    max_host_version  VARCHAR(32),                 -- 最高宿主版本
    java_version      VARCHAR(16)  NOT NULL DEFAULT '17', -- Java版本
    type              VARCHAR(32)  NOT NULL DEFAULT 'FUNCTIONAL', -- 'UI' 或 'FUNCTIONAL'
    status            VARCHAR(32)  NOT NULL DEFAULT 'INSTALLED',
    jar_path          VARCHAR(512) NOT NULL,
    jar_sha256        VARCHAR(64),                  -- 宿主验证的JAR SHA-256
    signature         BLOB,                         -- JAR分离签名原始字节
    signer_id         VARCHAR(128),                 -- 签名者ID
    frontend_entry    VARCHAR(512),                 -- 前端JS入口
    frontend_sha384   VARCHAR(96),                  -- 前端文件SHA-384（SRI）
    provider          VARCHAR(128),
    error_message     TEXT,
    installed_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

安装成功后 `jar_path` 保存 `pluginsRoot/.snapshots` 下的宿主快照路径，不保存上传源路径。应用层签名安装流程要求 `jar_sha256`、`signature`、`signer_id` 有效，数据库迁移为兼容旧数据仍允许空值。

`PluginManagerService` 在 PF4J/Flyway 前按表结构校验最终安装记录：`plugin_id(64)`、`name(128)`、`description(512)`、`type(32)`、`jar_path(512)`、`jar_sha256(64)`、`signer_id(128)`、`frontend_entry(512)`、`frontend_sha384(96)`、`provider(128)`，并限制 `signature` 不超过 MySQL `BLOB` 的 65535 字节。无旧记录时 INSERT；旧记录仅在 `status=UNINSTALLED`、`signer_id` 与新包一致且无残留 wrapper 时允许继续，并在迁移后按旧 `status/jar_path/signer_id` 条件更新。其他已有记录在 PF4J/Flyway 前拒绝；该机制不是跨实例锁。

`frontend_entry` 当前不是员工端脚本 URL 的信任来源；员工清单服务按插件 ID 固定生成 `/plugins/{pluginId}/index.js`。

## 插件配置

配置 CRUD、敏感值加密和插件侧只读 `PluginConfig` 已实现。`plugin_id` 是命名空间，数据库只保存裸 `config_key`；列表查询限定 `plugin_id`，单项读取、更新和删除同时限定 `plugin_id` 与 `config_key`。

```sql
CREATE TABLE sys_plugin_config (
    plugin_id        VARCHAR(64)  NOT NULL,
    config_key       VARCHAR(128) NOT NULL,
    config_value     TEXT,
    value_type       VARCHAR(32)  NOT NULL DEFAULT 'STRING', -- STRING/INT/BOOL/SECRET
    default_value    TEXT,
    description      VARCHAR(256),
    requires_restart TINYINT      NOT NULL DEFAULT 0, -- 修改后是否需要重启
    is_secret        TINYINT      NOT NULL DEFAULT 0, -- 是否敏感配置
    version          BIGINT       NOT NULL DEFAULT 1, -- 乐观锁版本
    is_deleted       TINYINT      NOT NULL DEFAULT 0, -- 删除墓碑
    updated_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (plugin_id, config_key)
);
```

应用层规则：

- `config_key` 匹配 `^[a-z0-9][a-z0-9._-]{0,127}$`；单插件最多 128 个配置键命名空间，墓碑仍占用原命名空间但允许原键重建，单值或默认值按 UTF-8 最多 16 KiB。配置 PUT 请求体在 JSON 反序列化前限制为 256 KiB。
- `value_type` 只允许 `STRING / INT / BOOL / SECRET`。`INT` 规范化为 64 位十进制，`BOOL` 只保存 `true / false`；已创建配置不能原地改变类型。
- 管理 API 创建或更新非敏感配置时，`config_value` 与 `default_value` 不能同时为空；允许只提供 `default_value`。插件读取优先使用 `config_value`，其为空时回退 `default_value`。
- `version` 是并发令牌：首次创建为 1，更新、删除和删除后重建均原子加 1；首次创建只接受 `expectedVersion=0`，墓碑重建必须提交 DELETE 返回的当前墓碑版本，更新和删除 SQL 同时限定 `(plugin_id, config_key, version, is_deleted)`。删除把 `config_value/default_value/description` 等内容清空，仅保留 `(plugin_id, config_key, version, is_deleted=1)` 墓碑；原删除版本可幂等重试并恢复该墓碑版本，不再次递增或重复审计。列表和插件读取只统计 `is_deleted=0`，命名空间配额统计全部行，从而同时避免 ABA 和循环创建/删除不同键造成的无界表增长。`updated_at` 只有秒级展示用途，不作为并发令牌。
- `SECRET` 强制 `is_secret=1` 且 `default_value=NULL`。`config_value` 保存 `v1:` 前缀的 AES-256-GCM envelope，每次使用随机 12 字节 nonce，AAD 绑定插件 ID 和配置键；管理 API 永不返回明文或密文。
- 加密主密钥来自 `WORKFORCE_PLUGIN_CONFIG_ENCRYPTION_KEY_BASE64`，必须解码为 32 字节。缺失密钥时所有敏感 PUT fail closed，格式非法时应用启动失败；`value=NULL` 的元数据更新也必须先用当前密钥成功解密原密文。历史明文、损坏密文或错钥只能提交新值重新加密或删除，插件读取不会回退明文。
- 表不设置到 `sys_plugin` 的级联外键。卸载进入 `UNINSTALLED` 时配置保留；同 `signerId` 的内部替换安装继续保留配置，并在成功后恢复为 `INSTALLED`。

密文当前没有 key ID、多密钥、自动轮换或重加密流程。灾备必须分别保存数据库和原主密钥并成对恢复；直接替换或丢失主密钥会使既有敏感配置不可解密。

V58 新增 `ADMIN_PLUGIN_MANAGE` 并授予 `SUPER_ADMIN`。权限 ID 和关系 ID 均按当前最大值后动态分配，不复用固定 ID，也不覆盖已有权限或角色关系。

## 插件写操作幂等账本

```sql
CREATE TABLE sys_plugin_operation_idempotency (
    plugin_id        VARCHAR(64)  NOT NULL,
    operation_code   VARCHAR(128) NOT NULL,     -- 写操作编码（如 LEAVE_APPROVE）
    idempotency_key  VARCHAR(128) NOT NULL,     -- 调用方幂等键

);
```

该表只用于事件订阅等宿主写操作，不保存 HTTP 动作响应。

## HTTP 插件动作幂等与响应回放

```sql
CREATE TABLE sys_plugin_action_idempotency (
    plugin_id        VARCHAR(64)  COLLATE utf8mb4_bin NOT NULL,
    action_code      VARCHAR(128) COLLATE utf8mb4_bin NOT NULL,
    caller_type      VARCHAR(16)  CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    caller_id        BIGINT       NOT NULL,
    idempotency_key  VARCHAR(128) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    request_hash     CHAR(64)     CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    status           VARCHAR(16)  CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    claim_token      CHAR(36)     CHARACTER SET ascii COLLATE ascii_bin NULL,
    response_json    JSON         NULL,
    created_at       DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    expires_at       DATETIME(6)  NULL,
    PRIMARY KEY (plugin_id, action_code, caller_type, caller_id, idempotency_key),
    INDEX idx_plugin_action_idempotency_expiry (status, expires_at)
);
```

`IN_PROGRESS` 的 `expires_at` 为 `NULL`，不会按时间自动重领或清理；进程崩溃、序列化失败或最终写库状态不确定时，记录保持 fail closed，需人工确认副作用后恢复。`COMPLETED.expires_at` 由数据库 `CURRENT_TIMESTAMP(6)` 计算 24 小时响应重放期限，过期后允许新请求复用该键。`claim_token` 只在执行中存在，完成或释放必须带 token 条件。响应仅保存严格校验的 JSON，流式序列化上限为 256 KiB；定时任务每轮最多分 100 批删除过期完成记录。同 ID 替换安装保留该表全部记录，不能通过换包释放不确定副作用。

## Flyway 迁移策略

### 历史表命名规则

每个插件使用独立的 Flyway 历史表，表名格式：

```
flyway_plugin_{sanitized_plugin_id}
```

实际表名必须不超过 61 字符，为 Flyway 自动生成的 `<table>_pk` 主键名预留 3 个字符，满足 MySQL 64 字符标识符上限。

命名算法：

1. 插件 ID 为空时拒绝。
2. 非字母、数字、下划线替换为 `_`，清理结果最多保留 50 字符。
3. 原 ID 已安全且长度不超过 47 时，直接使用该 ID。
4. 其他情况使用“清理结果前 34 字符 + `_` + 原始插件 ID 的 SHA-256 前 12 位十六进制”，避免长 ID、非法字符替换和截断造成简单碰撞。

最终 `flyway_plugin_` 前缀加 history ID 的总长度不超过 61。

### 迁移脚本位置

插件 JAR 内的 `db/migration/` 目录：

```
leave-plugin.jar
├── plugin.properties
├── plugin.json
└── db/                       # 可选
    └── migration/
        ├── V1__init_leave_tables.sql
        └── V2__add_leave_columns.sql
```

没有 `db/migration/` 时宿主直接跳过迁移。前端 `index.js` 独立构建和部署，不在后端 JAR 内。

### 迁移执行时机

1. 当前仅在 `PluginManagerService.install(...)` 中执行迁移，输入是宿主 JAR 快照。
2. 脚本先从 JAR 提取到临时目录，再由 Flyway 执行；结束后删除临时目录。
3. JAR 没有迁移目录时跳过；迁移失败时安装失败且不会启动插件。
4. 同 ID 内部替换也会复用原 history 执行待执行迁移，但插件升级/降级 API、版本方向限制、回滚和升级历史写入仍未实现。
5. 字段超长、非 `UNINSTALLED` 重复 ID、签名者漂移或残留 wrapper 会在 PF4J/Flyway 前拒绝；合格 `UNINSTALLED` 记录可继续替换。
6. Flyway 仍先于首次 INSERT 或替换 UPDATE；最终写入失败或竞争时，已执行的 MySQL DDL 和 history 可能保留，不能承诺自动回滚。

### 迁移脚本命名

```
V1__init_leave_tables.sql
V2__add_leave_columns.sql
```

**注意**：不使用插件ID前缀，因为每个插件有独立的history表。

### 卸载策略

- 卸载插件时**不删除数据库表**
- 插件记录保留为 `UNINSTALLED`，插件业务数据和 `sys_plugin_config` 配置也保留
- 配置管理 GET 仍可脱敏查询保留项，PUT 拒绝 `UNINSTALLED`，授权管理员可通过带版本的单项 DELETE 显式清理配置
- 宿主内部 `install(...)` 可将同 `signerId` 且运行时已清理的 `UNINSTALLED` 记录条件替换为 `INSTALLED`，但不自动启用。业务表、Flyway history、配置、能力、可见范围、动作权限、HTTP 动作幂等记录和入向依赖保留；宿主操作幂等记录、事件订阅和该插件的出向依赖清理
- 插件业务表的彻底清理仍需管理员单独执行 SQL，配置单项删除不能代替业务数据清理

## 版本升级记录

表已创建；当前没有插件升级/降级 API，也没有写入该表的完整流程。同 ID 替换不会写 `sys_plugin_upgrade_history`。

```sql
CREATE TABLE sys_plugin_upgrade_history (
    id               BIGINT       PRIMARY KEY AUTO_INCREMENT,
    plugin_id        VARCHAR(64)  NOT NULL,
    from_version     VARCHAR(32),
    to_version       VARCHAR(32)  NOT NULL,
    upgrade_type     VARCHAR(32)  NOT NULL,     -- INSTALL/UPGRADE/DOWNGRADE
    status           VARCHAR(32)  NOT NULL,     -- SUCCESS/FAILED
    error_message    TEXT,
    upgraded_at      DATETIME     NOT NULL,
    INDEX idx_plugin_id (plugin_id)
);
```

## 生命周期明细表（规划，尚未创建）

当前生命周期状态和错误信息直接保存在 `sys_plugin.status`、`sys_plugin.error_message`；活跃请求计数只存在于单 JVM `PluginLifecycleGuard` 内存中。以下独立表尚无 Flyway 迁移，不是当前数据库契约：

```sql
CREATE TABLE sys_plugin_lifecycle (
    plugin_id        VARCHAR(64)  PRIMARY KEY,
    status           VARCHAR(32)  NOT NULL,     -- INSTALLED/ACTIVE/STOPPED/ERROR/DISABLING
    last_started_at  DATETIME,
    last_stopped_at  DATETIME,
    last_error_at    DATETIME,
    last_error_msg   TEXT,
    active_requests  INT          DEFAULT 0,    -- 当前活跃请求数
    restart_required TINYINT      DEFAULT 0,    -- 是否需要重启
    updated_at       DATETIME     NOT NULL
);
```
