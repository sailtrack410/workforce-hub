# 插件化工作台 - 数据库设计

以下“已创建”表以 Flyway `V52`、`V54`、`V55` 为准。表存在不代表对应管理 API 或完整业务流程已经实现。

## 插件注册表

```sql
CREATE TABLE sys_plugin (
    plugin_id         VARCHAR(64)  PRIMARY KEY,
    name              VARCHAR(128) NOT NULL,
    description       VARCHAR(512),
    version           VARCHAR(32)  NOT NULL,
    sdk_version       VARCHAR(32)  NOT NULL DEFAULT '1.0.0', -- SDK版本
    min_host_version  VARCHAR(32),                 -- 最低宿主版本
    max_host_version  VARCHAR(32),                 -- 最高宿主版本
    java_version      VARCHAR(16)  NOT NULL DEFAULT '17', -- Java版本
    type              VARCHAR(32)  NOT NULL DEFAULT 'FUNCTIONAL', -- 'UI' 或 'FUNCTIONAL'
    status            VARCHAR(32)  NOT NULL DEFAULT 'INSTALLED',
    jar_path          VARCHAR(512) NOT NULL,
    jar_sha256        VARCHAR(64),                  -- 宿主验证的JAR SHA-256
    signature         BLOB,                         -- JAR分离签名原始字节
    signer_id         VARCHAR(128),                 -- 签名者ID
    frontend_entry    VARCHAR(512),                 -- 前端JS入口
    frontend_sha384   VARCHAR(96),                  -- 前端文件SHA-384（SRI）
    provider          VARCHAR(128),
    error_message     TEXT,
    installed_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

安装成功后 `jar_path` 保存 `pluginsRoot/.snapshots` 下的宿主快照路径，不保存上传源路径。应用层签名安装流程要求 `jar_sha256`、`signature`、`signer_id` 有效，数据库迁移为兼容旧数据仍允许空值。

`PluginManagerService` 在 PF4J/Flyway 前按表结构校验最终安装记录：`plugin_id(64)`、`name(128)`、`description(512)`、`type(32)`、`jar_path(512)`、`jar_sha256(64)`、`signer_id(128)`、`frontend_entry(512)`、`frontend_sha384(96)`、`provider(128)`，并限制 `signature` 不超过 MySQL `BLOB` 的 65535 字节；同时查询并拒绝当前已存在的插件 ID。该检查是应用层前置保护，不是跨实例唯一性锁。

`frontend_entry` 当前不是员工端脚本 URL 的信任来源；员工清单服务按插件 ID 固定生成 `/plugins/{pluginId}/index.js`。

```sql
CREATE TABLE sys_plugin_event_subscription (
```

## 插件写操作幂等账本

```sql
CREATE TABLE sys_plugin_operation_idempotency (
```

## Flyway 迁移策略

### 历史表命名规则

每个插件使用独立的 Flyway 历史表，表名格式：

```
flyway_plugin_{sanitized_plugin_id}
```

实际表名必须不超过 61 字符，为 Flyway 自动生成的 `<table>_pk` 主键名预留 3 个字符，满足 MySQL 64 字符标识符上限。

命名算法：

1. 插件 ID 为空时拒绝。
2. 非字母、数字、下划线替换为 `_`，清理结果最多保留 50 字符。
3. 原 ID 已安全且长度不超过 47 时，直接使用该 ID。
4. 其他情况使用“清理结果前 34 字符 + `_` + 原始插件 ID 的 SHA-256 前 12 位十六进制”，避免长 ID、非法字符替换和截断造成简单碰撞。

最终 `flyway_plugin_` 前缀加 history ID 的总长度不超过 61。

### 迁移脚本位置

插件 JAR 内的 `db/migration/` 目录：

```
leave-plugin.jar
├── plugin.properties
├── plugin.json
└── db/                       # 可选
    └── migration/
        ├── V1__init_leave_tables.sql
        └── V2__add_leave_columns.sql
```

没有 `db/migration/` 时宿主直接跳过迁移。前端 `index.js` 独立构建和部署，不在后端 JAR 内。

### 迁移执行时机

1. 当前仅在 `PluginManagerService.install(...)` 中执行迁移，输入是宿主 JAR 快照。
2. 脚本先从 JAR 提取到临时目录，再由 Flyway 执行；结束后删除临时目录。
3. JAR 没有迁移目录时跳过；迁移失败时安装失败且不会启动插件。
4. 插件升级 API 尚未实现，不能把“升级时自动迁移”视为当前能力。
5. 最终安装记录字段超长和检查时已存在的插件 ID 会在 PF4J/Flyway 前拒绝，不会执行迁移。
6. Flyway 仍先于 `sys_plugin` 插入；数据库瞬时失败或多实例并发安装竞态可能使后续持久化失败，已执行的 MySQL DDL 和 history 仍可能保留，不能承诺自动回滚。

### 迁移脚本命名

```
V1__init_leave_tables.sql
V2__add_leave_columns.sql
```

**注意**：不使用插件ID前缀，因为每个插件有独立的history表。

### 卸载策略

- 卸载插件时**不删除数据库表**
- 插件记录保留为 `UNINSTALLED`，插件业务数据也保留
- 当前 `install(...)` 对任意已存在 ID 都会拒绝，包括 `UNINSTALLED`；同 ID 重装/替换流程尚未实现
- 如需彻底清理，由管理员手动执行SQL

## 版本升级记录

表已创建；当前没有插件升级/降级 API，也没有写入该表的完整流程。

```sql
CREATE TABLE sys_plugin_upgrade_history (
    id               BIGINT       PRIMARY KEY AUTO_INCREMENT,
    plugin_id        VARCHAR(64)  NOT NULL,
    from_version     VARCHAR(32),
    to_version       VARCHAR(32)  NOT NULL,
    upgrade_type     VARCHAR(32)  NOT NULL,     -- INSTALL/UPGRADE/DOWNGRADE
    status           VARCHAR(32)  NOT NULL,     -- SUCCESS/FAILED
    error_message    TEXT,
    upgraded_at      DATETIME     NOT NULL,
    INDEX idx_plugin_id (plugin_id)
);
```

## 生命周期明细表（规划，尚未创建）

当前生命周期状态和错误信息直接保存在 `sys_plugin.status`、`sys_plugin.error_message`；活跃请求计数只存在于单 JVM `PluginLifecycleGuard` 内存中。以下独立表尚无 Flyway 迁移，不是当前数据库契约：

```sql
CREATE TABLE sys_plugin_lifecycle (
    plugin_id        VARCHAR(64)  PRIMARY KEY,
    status           VARCHAR(32)  NOT NULL,     -- INSTALLED/ACTIVE/STOPPED/ERROR/DISABLING
    last_started_at  DATETIME,
    last_stopped_at  DATETIME,
    last_error_at    DATETIME,
    last_error_msg   TEXT,
    active_requests  INT          DEFAULT 0,    -- 当前活跃请求数
    restart_required TINYINT      DEFAULT 0,    -- 是否需要重启
    updated_at       DATETIME     NOT NULL
);
```
