# 插件化工作台 - 总览

## 设计目标

当前 v0.1 验证以下插件能力：
- 后端 JAR 插件热加载（基于 PF4J）
- 前端组件动态注册与渲染（Host SDK 方案）
- 按宿主数据库中的可见范围过滤员工入口
- 插件生命周期管理（安装、启用、停用、卸载）
- 管理员按插件命名空间维护配置，插件通过只读 `PluginContext.getConfig()` 获取有效值

## 插件类型

| 类型     | 说明                      | 管理端                | 员工端               |
|----------|---------------------------|-----------------------|----------------------|
| UI插件   | 带前端组件，提供用户界面  | 管理页面尚未实现      | 符合清单条件时显示   |
| 功能插件 | 纯后端，提供API或定时任务 | 管理页面尚未实现      | 不显示               |

示例：
- UI插件：假期管理（有余额页面、请假表单）
- 功能插件：自动考勤计算（定时任务，无页面）、消息推送网关（纯API）

## 当前插件状态

| 状态 | 数据库存储值 | 说明 |
|------|--------------|------|
| INSTALLED | `INSTALLED` | 已安装，未启用 |
| ACTIVE | `ACTIVE` | 正常运行中 |
| STOPPED | `STOPPED` | 已停用 |
| DISABLING | `DISABLING` | 入口已关闭，等待请求排空 |
| ERROR | `ERROR` | 生命周期或恢复失败 |
| UNINSTALLED | `UNINSTALLED` | 已卸载，注册记录、业务数据和配置保留 |

主流程为 `INSTALLED → ACTIVE → DISABLING → STOPPED`；卸载成功进入 `UNINSTALLED`，生命周期失败进入 `ERROR`。当前安装存在性检查不区分状态，`UNINSTALLED` 不能直接同 ID 重装。保留配置仍可由管理员脱敏查询，并通过带版本的单项 DELETE 显式清理；PUT 拒绝 `UNINSTALLED`。

## 状态颜色（管理端规划）

| 状态           | 颜色 | 图标 |
|----------------|------|------|
| 运行中         | 绿色 | ●    |
| 已停用         | 灰色 | ●    |
| 异常           | 红色 | ●    |
| 已安装(未启用) | 黄色 | ●    |

## 操作按钮映射（管理端规划）

管理端插件页面和配置编辑界面尚未实现；下表仅表示规划交互。

| 状态   | 可用操作         |
|--------|------------------|
| 运行中 | 停用、配置、卸载 |
| 已停用 | 启用、配置、卸载 |
| 异常   | 重试、停用、卸载 |
| 已安装 | 启用、卸载       |

## 设计规则

- 只显示**已启用且带前端的插件**（UI插件 + ACTIVE状态）
- 不显示插件状态（员工不需要知道）
- 不显示功能插件（纯后端的不出现）
- 按 `ALL / USER / DEPT / POSITION / MANAGER` 可见范围过滤
- 插件 ID 和 SRI 不合法时不进入员工清单
- 前端路径固定为 `/plugins/{pluginId}/index.js`
- 当前响应没有 `directory`、`order` 或 `icon`，插件作为工作台直接入口加入
