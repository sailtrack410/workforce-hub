# 插件化工作台 - 前端架构

## 当前 v0.1 方案

员工端使用 Host SDK + IIFE 单文件加载。插件不读取 `window.Vue`，只通过 `window.__WORKFORCE_HOST__` 使用宿主暴露的 Vue API 并注册组件。

前端脚本路径在开发和生产代码中均固定为：

```text
/plugins/{pluginId}/index.js
```

当前没有 `/api/plugin-assets/**` 资源接口，也没有 `/plugins/{pluginId}.js` 协议。

---

## Host SDK

实现文件：`employee-web/src/core/host-sdk.ts`。

```typescript
export interface PluginRegistration {
  id: string;
  name: string;
  component: () => Promise<Component>;
}

export interface WorkforceHostSdk {
  readonly Vue: typeof Vue;
  register(id: string, registration: PluginRegistration): void;
  getPlugin(id: string): PluginRegistration | undefined;
  getAllPlugins(): ReadonlyMap<string, PluginRegistration>;
}
```

当前约束：

- `initHostSdk()` 在 Vue 应用挂载前调用，重复调用返回同一实例。
- 全局属性不可写、不可重新配置，SDK 对象被冻结。
- 注册 ID 必须非空并与 `registration.id` 一致。
- 名称必须非空，`component` 必须是函数。
- 重复 ID 直接拒绝，不覆盖已有插件。
- 查询结果返回副本，调用方不能修改内部注册表。
- v0.1 只暴露 Vue，不暴露 Vue Router、Pinia 或内部 store。

全局 SDK 不暴露 `unregister`、`clear` 或 `reset`，插件脚本不能注销其他插件。宿主通过模块内部 API 在清单重新加载时清空注册表；退出会话时除清空运行时外还执行整页重载，以清除插件在宿主 Realm 中创建的定时器、事件监听和全局副作用。运行中单插件停用后的事件监听、样式等资源清理仍未实现。

## 员工插件清单 API

```text
GET /api/employee/plugins/mine
```

响应数据项：

```json
{
  "id": "hello-plugin",
  "name": "Hello Plugin",
  "frontendEntry": "/plugins/hello-plugin/index.js",
  "integrity": "sha384-<64字符Base64摘要>"
}
```

后端当前只返回：

- 状态为 `ACTIVE` 的 `UI` 插件。
- 当前登录员工符合 `ALL / USER / DEPT / POSITION / MANAGER` 可见范围的插件。
- ID 符合 `^[a-z0-9-]{1,64}$` 且 SRI 符合当前 SHA-384 格式的插件。

插件类型和 `integrity` 以签名 JAR 中 `plugin.json` 的持久化及恢复复验结果为准，`frontendEntry` 由后端按签名插件 ID 固定生成。员工端加载器只使用 `id` 和 `integrity`，不会执行数据库或响应中提供的任意脚本 URL。

## 插件加载器

实现文件：`employee-web/src/core/plugin-loader.ts`。

核心流程：

1. 校验插件 ID 与 SRI。
2. 要求 `window.__WORKFORCE_HOST__` 已初始化。
3. 同一插件 pending 时，相同 SRI 复用 Promise，不同 SRI 直接拒绝。
4. 已注册插件只有在 loader 已验证且 SRI 完全一致时才复用；外部预注册、注册来源不属于当前脚本或摘要漂移均 fail closed。
5. 创建异步 `<script>`，路径固定为 `/plugins/{pluginId}/index.js`，始终设置 `integrity`。
6. `load` 后确认目标插件由当前 `<script>` 调用 `host.register(...)`，再记录已验证 SRI；否则移除脚本并失败。
7. 加载失败或超过 10 秒时移除脚本、使脚本失效并清理 pending 状态，允许后续重试。
8. 运行时重置会清注册表、摘要、已加载和 pending 脚本，并使旧脚本后续 `register(...)` 失效，避免污染新会话。

`register(...)` 必须在当前 IIFE `<script>` 的同步执行期间调用；当浏览器的 `document.currentScript` 为空时宿主拒绝注册，插件不得把注册动作放进异步回调。

当前没有根据 `import.meta.env.DEV` 绕过 SRI，也没有开发专用 URL 分支。

## 清单状态与工作台挂载

`usePluginsStore` 在员工已认证工作区加载时调用 `employeeApi.plugins.mine()`，在核心消息工作区初始化之外使用 `Promise.allSettled` 并行加载脚本：单个插件失败不会阻塞核心工作区，失败原因按插件 ID 记录；单个脚本最多等待 10 秒。

加载成功后：

- `shell.rebuildWorkbench(...)` 只把清单中且已加载的插件加入工作台。
- 插件 ID 不得覆盖 `oa`、`attendance`、`balance` 等保留入口。
- 插件清单尚未解析完成时，插件路由保持等待；解析完成后不存在或不可用的插件回退到 `oa`。
- `PluginWorkbenchHost` 调用注册项的 `component()`，提供加载态、错误态、重试和 Vue 错误捕获。
- 每次新清单 generation 开始时先清理上一代插件运行时，再加载最新清单；退出登录时先清空员工插件 store、Host SDK 注册表、摘要和已跟踪脚本，再整页重载，避免旧插件顶层副作用跨账号存活。

## 插件入口

当前 hello-plugin 样板：

```typescript
const host = window.__WORKFORCE_HOST__;
if (!host) {
  throw new Error('宿主 SDK 未初始化：window.__WORKFORCE_HOST__ 不存在');
}

const { defineComponent, h } = host.Vue;

const component = defineComponent({
  name: 'HelloPluginView',
  setup: () => () => h('div', { class: 'hello-plugin' }, 'Hello Plugin'),
});

host.register('hello-plugin', {
  id: 'hello-plugin',
  name: 'Hello Plugin',
  component: () => Promise.resolve(component),
});
```

插件入口不使用动态 `import()`，也不直接导入 Vue。当前样板没有向插件暴露 Router 或 Pinia。

## IIFE 构建

当前 PoC 配置位于 `employee-web/vite.plugin-poc.config.ts`：

- 入口：`plugins/hello-plugin/frontend/src/index.ts`
- 格式：`iife`
- 输出：`employee-web/dist/plugins/hello-plugin/index.js`
- `cssCodeSplit=false`
- `sourcemap=false`
- 测试验证输出目录只有 `index.js`，bundle 不含静态或动态 import，执行后只注册 `hello-plugin`

`deploy/nginx/Dockerfile` 当前会在 employee-web 构建后执行 `npm run build:plugin-poc`。这只是 hello-plugin 的固定 PoC 构建，不是任意插件的通用发布系统。

## Nginx 资源边界

当前 Nginx 只开放：

```nginx
location ~ ^/plugins/[a-z0-9-]+/index\.js$ { ... }
```

该路径只允许 GET/HEAD，关闭目录索引，添加 `nosniff` 和 `Cache-Control: no-store`；其他 `/plugins/` 路径返回 404。

开发服务器当前没有 `/plugins` 代理或插件热更新服务器配置。本地验证需要先生成并以相同固定路径提供脚本；旧文档中的 5175 插件 dev server 不是已实现能力。
