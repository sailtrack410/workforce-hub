## 二、测试目标

本轮测试目标：

- 验证部门、岗位、员工写侧接口可正常新增与更新
- 验证树结构循环与上下级循环校验生效
- 验证员工生命周期状态机校验生效
- 验证员工账号启停与生命周期联动规则生效
- 验证写侧与读侧接口可联动回查

## 五、测试覆盖策略

### 5.1 功能覆盖

- 新增部门
- 修改部门
- 新增岗位
- 修改岗位
- 新增员工
- 修改员工
- 生命周期流转
- 账号创建 / 更新

### 5.2 规则覆盖

- 部门编码唯一
- 岗位编码唯一
- 工号唯一
- 部门树循环拦截
- 上下级循环拦截
- 生命周期非法流转拦截
- 待入职 / 已离职账号启用拦截
- 离职自动停用账号

### 5.3 契约覆盖

- 创建接口返回对象 ID
- 更新接口返回 `code=0 + data=null`
- 业务规则失败返回 `HTTP 200 + code!=0`
- 更新后可被读侧接口回查

## 六、测试用例明细

| 用例 ID | 优先级 | 接口 | 用例名称 | 前置条件 | 预期结果 |
| --- | --- | --- | --- | --- | --- |
| `ORG-WRITE-001` | P0 | `POST /api/admin/departments` | 正常新增部门 | 已登录后台管理员；父部门存在 | HTTP `200`；`code=0`；返回新部门 ID；读侧组织树可回查 |
| `ORG-WRITE-002` | P0 | `PUT /api/admin/departments/{id}` | 正常修改部门信息 | 已存在目标部门 | HTTP `200`；`code=0`；负责人、名称、状态更新生效 |
| `ORG-WRITE-003` | P0 | `PUT /api/admin/departments/{id}` | 拦截部门树循环 | 目标部门存在子部门 | HTTP `200`；`code=400`；提示不能挂到自己的子部门下面 |
| `ORG-WRITE-004` | P0 | `POST /api/admin/positions` | 正常新增岗位 | 已登录后台管理员 | HTTP `200`；`code=0`；返回岗位 ID；读侧岗位列表可回查 |
| `ORG-WRITE-005` | P1 | `PUT /api/admin/positions/{id}` | 修改岗位成功 | 岗位存在 | HTTP `200`；`code=0` |
| `ORG-WRITE-006` | P0 | `POST /api/admin/users` | 正常新增待入职员工 | 部门、岗位、直属上级存在 | HTTP `200`；`code=0`；返回员工 ID；读侧详情可回查默认司龄字段 |
| `ORG-WRITE-007` | P0 | `PUT /api/admin/users/{id}` | 正常修改员工档案 | 员工存在 | HTTP `200`；`code=0`；部门/岗位/上级变化生效 |
| `ORG-WRITE-008` | P0 | `PUT /api/admin/users/{id}` | 拦截上下级循环 | 已构造 A -> B 汇报关系 | HTTP `200`；`code=400`；提示直属上级不能是当前员工的下级 |
| `ORG-WRITE-009` | P0 | `PUT /api/admin/users/{id}/employment-status` | 合法生命周期流转 | 员工当前处于允许流转的状态 | HTTP `200`；`code=0`；状态变更成功 |
| `ORG-WRITE-010` | P0 | `PUT /api/admin/users/{id}/employment-status` | 拦截非法生命周期流转 | 员工当前状态不允许直达目标状态 | HTTP `200`；`code=400`；返回状态机错误提示 |
| `ORG-WRITE-011` | P0 | `PUT /api/admin/users/{id}/account` | 待入职员工禁止启用账号 | 员工状态为 `PENDING_ONBOARD` | HTTP `200`；`code=400`；提示当前员工状态不允许启用登录账号 |
| `ORG-WRITE-012` | P0 | `PUT /api/admin/users/{id}/account` | 试用期员工允许创建启用账号 | 员工状态已流转为 `PROBATION` | HTTP `200`；`code=0`；账号创建成功 |
| `ORG-WRITE-013` | P0 | `PUT /api/admin/users/{id}/employment-status` | 离职时自动停用账号 | 员工已有启用账号 | HTTP `200`；`code=0`；账号状态最终被改为 `DISABLED` |

## 七、自动化冒烟覆盖结论

当前仓库已将以下场景沉淀为自动化测试：

- 新增部门 + 读侧组织树回查
- 新增岗位 + 读侧岗位列表回查
- 新增员工 + 默认司龄字段回查
- 待入职员工禁止直接启用账号
- 生命周期从待入职 -> 试用期 -> 待离职 -> 已离职
- 离职后自动停用账号
- 部门树循环拦截
- 上下级循环拦截

对应自动化测试类：

- `server/src/test/java/com/workforcehub/org/ModuleOrgWriteApiIntegrationTest.java`

## 八、执行建议

1. 登录后台管理员
2. 执行部门新增 / 编辑用例
3. 执行岗位新增 / 编辑用例

5. 执行生命周期与账号联动用例

### 8.2 回归通过标准

- 所有 P0 用例通过
- 写侧更新后读侧可正确回查
- 不出现 `500`
- 生命周期与账号状态联动结果符合规则
