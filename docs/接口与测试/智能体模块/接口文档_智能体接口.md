# API 文档：module-agent 智能体接口

## 1. 文档范围

| 项目 | 说明 |
| --- | --- |
| 模块 | `module-agent` |
| 当前状态 | 后台 Agent 治理、列表、详情、停用、版本、工具、ACL、发布、任务查询、任务工具调用明细、任务审计轨迹、任务运行指标、失败聚合、人工确认超时手动扫描、超时扫描批次查询已实现；员工端 Agent 列表、任务创建、人工确认继续、拒绝、取消已实现；IM 会话 Agent 已接入真实模型异步执行、成功回写、失败提示和幂等保护 |
| 认证方式 | 复用 Spring Session，后台接口必须使用管理员会话，员工接口必须使用员工会话 |
| 响应格式 | 统一 `R<T>`，`code=0` 表示接口调用成功，业务失败使用非 0 code |
| 数据库变更 | Agent 超时扫描使用 `V12__add_agent_timeout_job_records.sql`；IM 会话消息幂等使用 `V13__add_im_message_client_idempotency.sql`；IM WebSocket outbox 使用 `V14__add_im_event_outbox.sql` |

当前还不是完整 Agent 平台，暂不包含版本回滚、workflow 真实触发器、RAG、工具调用型会话 Agent 和后台告警监控。后台任务查询已提供分页列表、详情、工具调用明细、审计轨迹、运行指标和失败聚合入口；人工确认超时扫描已提供服务调用、后台手动触发、定时触发、数据库锁互斥、批次运行记录和后台批次查询；IM 会话 Agent 的前端接入契约详见 `../会话模块/接口文档_会话接口.md`。

## 2. 关键规则

### 2.1 Agent 发布规则

- Agent 创建后初始状态为 `DRAFT`。
- Agent 版本创建后初始状态为 `DRAFT`。
- 只有 `DRAFT` 版本允许绑定工具。
- 发布版本后：
  - 当前版本进入 `PUBLISHED`。
  - 同 Agent 旧发布版本归档为 `ARCHIVED`。
  - Agent 主表写入 `published_version_id` 并进入 `ACTIVE`。

### 2.2 ACL 规则

| subjectType | subjectId 语义 | 当前是否生效 |
| --- | --- | --- |
| `USER` | `org_user.id` | 是 |
| `DEPARTMENT` | `org_department.id`，按员工 `primary_dept_id` 判断 | 是 |
| `GROUP` | `im_conversation.id`，仅活跃群聊和活跃成员生效 | 是 |
| `ADMIN_USER` | `admin_user.id` | 可写入，后台委托管理暂未接入 |

| permCode | 当前语义 |
| --- | --- |
| `visible` | 员工可在 Agent 列表看到 |
| `use` | 员工可看到并创建任务 |
| `manage` | 预留给后续委托管理；当前员工端按可用权限处理，后台接口仍以管理员会话为准 |

### 2.3 工具调用规则

- 未绑定到当前发布版本的工具不能调用，任务创建前返回 `403`，不写 `agt_task`。
- `approvalMode=AUTO` 的 `SPI` 工具会同步执行。
- `approvalMode=REQUIRE_CONFIRM` 的工具会让任务进入 `WAITING_HUMAN_CONFIRM`，不执行工具。
- `WAITING_HUMAN_CONFIRM` 任务只能由任务触发员工继续、拒绝或取消。
- 人工同意继续后，任务恢复为 `RUNNING`，执行仍有效的待确认工具，成功后进入 `SUCCEEDED`。
- 人工拒绝后，任务进入 `REJECTED`；人工取消后，任务进入 `CANCELLED`。
- 人工确认超过 `waiting_deadline_at` 后，`AgentTaskTimeoutJobService` 可把任务自动收口为 `CANCELLED`，待确认工具日志写入 `TIMEOUT/CANCELLED`，并写入 `TASK_TIMEOUT_CANCELLED` 审计。
- 如果待确认工具绑定已失效或没有可继续执行的待确认工具，确认继续会返回 `409`，任务保持等待状态。
- `CONNECTOR` 工具第一批只允许定义和绑定；如果配置为 `AUTO` 执行，会生成 `FAILED` 任务并返回 `连接器工具执行器尚未接入`。
- 业务型工具执行失败时，接口仍返回 `code=0`，任务状态为 `FAILED`，并写入 `agt_tool_call_log` 和 `agt_audit_log`。

## 3. 后台接口

### 3.1 创建 Agent

`POST /api/admin/agents`

请求：

```json
{
  "agentCode": "ORG_HELPER",
  "agentName": "组织助手",
  "agentType": "QA",
  "identityMode": "SYSTEM_IDENTITY"
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "agentId": 2053519959787827201,
    "agentCode": "ORG_HELPER",
    "agentName": "组织助手",
    "agentType": "QA",
    "identityMode": "SYSTEM_IDENTITY",
    "publishedVersionId": null,
    "status": "DRAFT"
  },
  "requestId": "..."
}
```

字段约束：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `agentCode` | 是 | 最大 64 字符，服务端转大写，唯一 |
| `agentName` | 是 | 最大 128 字符 |
| `agentType` | 是 | `QA`、`PRE_REVIEW`、`REMINDER`、`AUTOMATION` |
| `identityMode` | 否 | 默认 `SYSTEM_IDENTITY`，也支持 `USER_DELEGATED` |

### 3.3 查询 Agent 详情

`GET /api/admin/agents/{agentId}`

返回 `AgentResponse`。不存在或已删除时返回 `code=404`、`message=Agent不存在`。

### 3.4 停用 Agent

`POST /api/admin/agents/{agentId}/disable`

处理规则：

- 只把 `agt_agent.status` 更新为 `INACTIVE`。
- 不清空 `published_version_id`。
- 后台详情继续可查。
- 员工端 Agent 列表不再展示。
- 员工端创建任务返回 `code=409`、`message=Agent未发布或未启用`。

### 3.8 授予 Agent ACL

`POST /api/admin/agents/{agentId}/acl`

请求：

```json
{
  "subjectType": "GROUP",
  "subjectId": 7301,
  "permCode": "use",
  "status": "ACTIVE"
}
```

说明：

- `GROUP` 的 `subjectId` 使用群聊 `im_conversation.id`。
- `GROUP` ACL 只对 `im_conversation.status=ACTIVE`、`im_conversation.conversation_type=GROUP`、`im_group_profile.status=ACTIVE` 且 `im_conversation_member.status=ACTIVE` 的成员生效。

### 3.9 发布 Agent 版本

`POST /api/admin/agents/versions/{versionId}/publish`

响应中的 `data.publishedVersionId` 应等于本次发布版本 ID，`data.status` 应为 `ACTIVE`。

`GET /api/admin/agent-tasks?pageNo=1&pageSize=20&status=SUCCEEDED`

支持查询参数：

| 参数 | 必填 | 说明 |

### 3.16 手动触发人工确认超时扫描

`POST /api/admin/agent-tasks/timeout-scan`

请求：

```json
{
  "batchSize": 10
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "jobRunId": "AGT-TIMEOUT-2055520000000000001",
    "triggerType": "MANUAL",
    "jobStatus": "SUCCESS",
    "batchSize": 10,
    "scannedCount": 1,
    "cancelledCount": 1,
    "skippedCount": 0,
    "errorMessage": null,
    "startedAt": "2026-05-11T08:43:28",
    "finishedAt": "2026-05-11T08:43:28"
  },
  "requestId": "..."
}
```

字段约束：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `batchSize` | 否 | 默认 100，最小 1，最大 500；显式传 `null` 时按默认 100 处理 |

处理规则：

- 扫描 `agt_task.status=WAITING_HUMAN_CONFIRM` 且 `waiting_deadline_at <= now` 的任务。
- 按 `waiting_deadline_at ASC, id ASC` 批量处理。
- 命中任务进入 `CANCELLED`，错误摘要为 `人工确认超时，任务已取消`。
- 待确认工具日志更新为 `approval_status=TIMEOUT`、`result_status=CANCELLED`。
- 每个实际取消成功的任务写入 `TASK_TIMEOUT_CANCELLED` 审计。
- 取消时再次校验任务状态和截止时间，避免并发扫描重复写审计。
- 每次手动扫描都会写入 `agt_task_timeout_job_run` 批次记录。
- 如果 `sys_job_lock` 中存在未过期的 `AGENT_TASK_TIMEOUT_SCAN` 锁，接口返回 `jobStatus=SKIPPED`，不取消任务。

处理规则：

- 默认按 `started_at DESC, id DESC` 排序，优先展示最近扫描批次。
- `triggerType` 和 `status` 会做枚举校验，不支持的值返回 `code=400`。
- 该接口只读查询 `agt_task_timeout_job_run`，不触发扫描、不修改任务、不释放锁。
- `status=SKIPPED` 表示本次扫描未拿到 `AGENT_TASK_TIMEOUT_SCAN` 锁，任务不会被取消。
- `status=FAILED` 表示扫描批次执行异常，`errorMessage` 只保留截断后的错误摘要，详细堆栈应看服务日志。

### 4.2.1 IM 会话 Agent 触发说明

前端做聊天式 Agent 对话时，不直接调用 `POST /api/employee/agents/{agentId}/tasks`。正确链路是：

1. `GET /api/employee/agents` 查询当前员工可用 Agent。
2. `POST /api/employee/im/agent-conversations` 创建或复用 Agent 会话。
3. `POST /api/employee/im/conversations/{conversationId}/messages` 向 Agent 会话发送 `TEXT` 消息。
4. 后端异步创建 `triggerType=CONVERSATION`、`contextType=IM_CONVERSATION` 的 Agent 任务。
5. 模型成功时 IM 写入 `senderType=AGENT` 消息并推送 `IM_AGENT_MESSAGE_CREATED`。
6. 模型失败时 IM 写入 `senderType=SYSTEM` 失败提示并推送 `IM_AGENT_REPLY_FAILED`。

第一版会话 Agent 只把当前用户消息和 Agent 版本系统提示发给 OpenAI 兼容模型，不做多轮上下文、工具调用、RAG 或知识库引用。

模型失败分类包括：

| failureType | 含义 |
| --- | --- |
| `CONFIG_MISSING` | 模型未启用、baseUrl、apiKey 或 model 缺失，或版本模型配置 JSON 不合法 |
| `AUTH_FAILED` | 模型服务返回 `401` 或 `403` |
| `TIMEOUT` | 模型调用超时或被中断 |
| `RATE_LIMITED` | 模型服务返回 `429` |
| `PROVIDER_ERROR` | 模型服务网络错误、5xx 或其他非 2xx |
| `INVALID_RESPONSE` | 模型响应为空或不可解析 |
| `UNKNOWN` | 未归类异常 |

这些失败分类会进入 Agent 任务失败记录和审计；员工端只展示 IM 系统提示，不暴露供应商原始错误。

### 4.5 人工确认超时扫描服务

后台 HTTP 入口为 `POST /api/admin/agent-tasks/timeout-scan`，后端内部服务为：

```java
AgentTaskTimeoutJobService#cancelExpiredWaitingTasks(int batchSize)
AgentTaskTimeoutJobService#runTimeoutScan(String triggerType, int batchSize)
```

处理规则：

| 项目 | 说明 |
| --- | --- |
| 扫描范围 | `agt_task.status=WAITING_HUMAN_CONFIRM` 且 `waiting_deadline_at <= now` |
| 批量顺序 | 按 `waiting_deadline_at ASC, id ASC` |
| 批次大小 | `batchSize` 必须大于 0，单批最大按服务内上限 500 截断 |
| 任务终态 | `CANCELLED` |
| 任务错误摘要 | `人工确认超时，任务已取消` |
| 工具日志 | `approval_status=TIMEOUT`，`result_status=CANCELLED` |
| 审计动作 | `TASK_TIMEOUT_CANCELLED` |
| 批次记录 | `agt_task_timeout_job_run` 记录运行编号、触发方式、状态、批次大小、扫描数、取消数、跳过数和错误摘要 |
| 并发边界 | `sys_job_lock` 按 `lock_name=AGENT_TASK_TIMEOUT_SCAN` 做数据库互斥；取消时再次校验任务状态和截止时间，只有实际更新成功才写审计 |
| 定时入口 | `scheduledTimeoutScan()` 使用 `@Scheduled`，默认初始延迟 60 秒、固定延迟 60 秒 |
| 测试环境 | 集成测试基线通过 `workforce.agent.timeout-scan.enabled=false` 关闭定时副作用，测试用例显式调用服务入口 |

相关配置：

| 配置项 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `workforce.agent.timeout-scan.enabled` | `AGENT_TIMEOUT_SCAN_ENABLED` | `true` | 是否启用定时扫描 |
| `workforce.agent.timeout-scan.batch-size` | `AGENT_TIMEOUT_SCAN_BATCH_SIZE` | `100` | 定时扫描批次大小 |
| `workforce.agent.timeout-scan.fixed-delay-ms` | `AGENT_TIMEOUT_SCAN_FIXED_DELAY_MS` | `60000` | 两次定时扫描之间的固定延迟 |
| `workforce.agent.timeout-scan.initial-delay-ms` | `AGENT_TIMEOUT_SCAN_INITIAL_DELAY_MS` | `60000` | 应用启动后的首次扫描延迟 |

## 7. 错误码与任务状态

| 场景 | HTTP | `code` | 说明 |
| --- | --- | --- | --- |
| 未登录 | 200/401 | 401 | 取决于安全链路拦截点 |
| 员工无权使用 Agent | 200 | 403 | 不创建任务 |
| Agent 未发布或未启用 | 200 | 409 | 不创建任务 |
| 后台查询不存在的 Agent | 200 | 404 | `Agent不存在` |
| 工具未绑定当前版本 | 200 | 403 | 不创建任务 |
| 输入 JSON 不合法 | 200 | 400 | 不创建任务 |
| 业务型工具执行失败 | 200 | 0 | 创建任务，任务状态为 `FAILED` |
| 高风险/需确认工具 | 200 | 0 | 创建任务，任务状态为 `WAITING_HUMAN_CONFIRM` |
| 他人确认或取消任务 | 200 | 403 | 只有任务触发员工可操作 |
| 非等待人工确认状态操作 | 200 | 409 | 只有 `WAITING_HUMAN_CONFIRM` 可确认或取消 |
| 无可继续执行待确认工具 | 200 | 409 | 绑定失效或待确认日志缺失时拒绝误成功 |
| 人工确认超时扫描 | 200 | 0 | 超过 `waiting_deadline_at` 的等待任务转为 `CANCELLED` |
| 超时扫描批次不合法 | 200 | 400 | `batchSize` 小于 1 或大于 500 |
| 超时扫描批次查询非法筛选 | 200 | 400 | 不支持的 `triggerType` 或 `status` |
| 后台任务指标/失败聚合 | 200 | 0 | 只读统计，不修改任务和日志 |
