# 任务派发与个人待办

## 业务边界

| 项目 | 团队任务 | 个人待办 |
|---|---|---|
| 用途 | 派给其他员工的工作 | 自己记录和安排的事项 |
| 创建人 | 派发人，取当前员工 ID | 所有人，取当前员工 ID |
| 负责人 | 有效的同部门同事或直属下属 | 无派发人、负责人字段 |
| 可见范围 | 派发人与负责人 | 仅本人 |
| 修改、重新分配、删除 | 仅派发人 | 仅本人 |
| 执行状态 | 仅负责人开始、完成、重开 | 本人完成、重开 |
| 时间 | 必须提供起止日期 | 可不设置时间 |
| 相互关系 | 不自动生成个人待办 | 不汇总任务、审批或会议 |

员工有效条件：未删除、`status=ACTIVE`，在职状态为 `PROBATION`、`ACTIVE` 或 `PENDING_OFFBOARD`。团队范围按现有主部门及直属管理关系判定；不存在额外的团队成员模型。普通成员可派发，不要求管理岗位。

新任务不能派给自己；个人事项使用个人待办。历史自己派给自己的任务仍可查询、完成或删除。

`groupId` 保留为关联信息，不授予访问或派发权限。个人待办的 `APPROVAL`、`MEETING`、`TASK`、`REMINDER` 为历史兼容的手动分类，不代表关联真实审批、会议或团队任务。

## 任务接口

路径前缀：`/api/employee/team-tasks`。返回使用现有 `R` 响应结构。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/assignees` | 当前派发人可选择的负责人，含 userId、realName、primaryDeptId |
| GET | `/` | 查询与自己有关的任务 |
| POST | `/` | 创建派发任务，初始状态 TODO |
| GET | `/{taskId}` | 查看任务 |
| PUT | `/{taskId}` | 派发人修改任务或重新分配 |
| PUT | `/{taskId}/status` | 负责人更新执行状态 |
| DELETE | `/{taskId}` | 派发人删除任务 |

列表参数：

| 参数 | 说明 |
|---|---|
| scope | `ALL`（默认）、`ASSIGNED`（我负责的）、`CREATED`（我派发的） |
| assigneeId | 进一步按负责人筛选，不能扩大可见范围 |
| status | TODO、IN_PROGRESS、DONE；兼容查询历史 IN_REVIEW |
| start / end | ISO 日期；查询与区间有交集的任务，可只给一侧边界 |

创建、修改请求沿用 title、description、assigneeId、startDate、endDate、groupId。标题最多128字符，描述最多1024字符，关联标识最多64字符；起止日期必填且开始不晚于结束。创建人及执行状态不能通过该请求覆盖。

任务响应保留原字段，新增 creatorName、assigneeName，以及 canEdit、canDelete、canStart、canComplete、canReopen。后续前端应按权限字段显示按钮；服务端仍独立鉴权。

负责人直接完成，无派发人验收步骤：

| 当前状态 | 可改为 |
|---|---|
| TODO | IN_PROGRESS、DONE |
| IN_PROGRESS | TODO、DONE |
| DONE | TODO（重开后可重新开始） |
| 历史 IN_REVIEW | TODO、IN_PROGRESS、DONE |

相同状态重复请求成功返回当前对象；新请求不允许进入 IN_REVIEW。重新分配负责人后，任务回到 TODO，旧负责人失去访问和执行权限。普通修改保留原执行状态。

## 个人待办接口

路径前缀：`/api/employee/personal-todos`，沿用创建、修改、列表、完成、重开和删除接口。

- ownerId 始终来自当前员工，不接受请求覆盖。
- 标题必填、最多128字符；备注最多1024字符。
- dueAt 可省略或为 null；存在时格式为 `yyyy-MM-dd HH:mm:ss`。
- 列表 category、status、start、end 均为可选参数；日期范围只返回有相应日期的事项，不设日期范围则包含无日期事项。
- 完成后再次完成不会改变原完成时间；重开恢复 PENDING 并清空完成时间。
- 管理员主体即使与员工 ID 相同，也不能进入个人待办服务。

## 错误与并发

| HTTP | 含义 |
|---|---|
| 400 | 输入格式、长度、日期范围、负责人 ID、状态或范围不合法；任务派给自己 |
| 401 | 未登录 |
| 403 | 非员工主体、操作角色不匹配，或负责人不在有效派发范围 |
| 404 | 记录不存在或当前员工不可见，两者不做区分 |
| 409 | 执行状态流转不允许，或写入前负责人/执行状态已发生变化 |

任务修改和状态写入同时比较数据库中的原负责人、原执行状态，避免过期请求覆盖重新分配或完成结果。

本次未修改数据库结构与前端界面。现有前端的派发候选人、操作按钮及“评审中”入口须在后续 UI 阶段对齐上述接口。
