# 团队任务协作接口

基础路径：`/api/employee/team-tasks`。沿用员工登录会话、CSRF、统一响应及任务对象权限。

| 方法 | 路径 | 请求 | 返回 |
| --- | --- | --- | --- |
| GET | `/lists` | 无 | 本人创建或本人参与任务所在的清单 |
| POST | `/lists` | `{content: 清单名称}` | 新清单 |
| PUT | `/lists/{listId}` | `{content: 清单名称}` | 重命名后的清单 |
| DELETE | `/lists/{listId}` | 无 | 删除空清单；非空返回 409 |
| PUT | `/{taskId}/watch?watching=true或false` | 无 | 当前任务详情 |
| POST | `/{taskId}/comments` | `{content: 评论正文}` | 当前任务详情 |
| POST | `/{taskId}/subtasks` | `{title: 标题, completed: false}` | 当前任务详情 |
| PUT | `/{taskId}/subtasks/{subtaskId}` | `{title: 标题, completed: 是否完成}` | 当前任务详情 |
| DELETE | `/{taskId}/subtasks/{subtaskId}` | 无 | 当前任务详情 |
| GET | `/{taskId}/attachments` | 无 | 附件列表及移除权限 |
| PUT | `/{taskId}/attachments/{attachmentRefId}` | 无 | 绑定后的附件列表 |
| DELETE | `/{taskId}/attachments/{attachmentRefId}` | 无 | 解除任务关联，保留原文件 |
| POST | `/{taskId}/attachments/{attachmentRefId}/download-tickets` | 无 | 任务范围下载票据 |
| GET | `/{taskId}/attachments/{attachmentRefId}/download/{ticketNo}` | 无 | 文件流 |

清单名称 1–64 字、子任务标题 1–128 字、评论 1–2000 字；去除首尾空白后校验。任务列表和详情新增 `groupName`、`watching`、`subtasks`；详情包含 `watcherNames` 与 `activities`。ID 按字符串使用，前端不转为 Number。

派发人可修改任务信息、维护子任务标题和增删子任务；负责人可完成或重开子任务。两者均可评论、关注及添加本人上传的个人文件。其他员工不能借助清单、评论或附件扩大任务访问范围；重新派发后旧负责人失去访问权限。清单拥有权不授予其他任务的阅读权限。

附件复用现有上传票据、确认上传及扫描链路。下载使用任务专用票据，签发与消费时均验证当前任务参与关系、附件绑定关系、文件删除及扫描状态。票据限定申请人、任务、附件、有效期并单次消费。原个人文件的访问权限不变。

`activities` 按创建时间及记录 ID 排序，区分 `CREATED`、`UPDATED`、`STATUS`、`SUBTASK`、`COMMENT`。完成子任务不会自动完成父任务。历史任务无创建事件时使用既有 `createdAt` 展示创建记录，不生成虚构记录。

数据结构由新增 Flyway `V73__add_team_task_collaboration.sql` 创建；保留已发布迁移。清单、子任务、关注、评论及附件绑定均持久化至后端。前端不使用浏览器存储代替业务持久化。

验收命令：`cd server && mvn -Dtest=TeamTaskCollaborationTest,TeamTaskAttachmentTest,TeamTaskAuthorizationTest,TaskTodoBusinessRulesTest test`；`cd hub-web && npm run test && npm run build`。
