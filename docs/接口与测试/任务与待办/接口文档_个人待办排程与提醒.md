# 个人待办排程与提醒

`POST /api/employee/personal-todos` 与 `PUT /api/employee/personal-todos/{todoId}` 沿用员工登录会话、CSRF 和本人数据权限。

| 字段 | 含义 |
| --- | --- |
| `title` | 必填，1–128 字 |
| `category` | `TASK`、`MEETING`、`REMINDER`、`APPROVAL` |
| `startAt` / `dueAt` | 可选起止时间，格式 `yyyy-MM-dd HH:mm:ss`，开始不能晚于截止 |
| `allDay` | 全天事项，至少提供一个日期；前端提交开始日 00:00:00 至结束日 23:59:59 |
| `reminderMinutes` | `null` 不提醒；可取 0、5、10、15、30、60、1440 |
| `note` | 可选，最多 1024 字 |

响应增加 `allDay`、`reminderMinutes`、`reminderAt`。提醒以开始时间优先、否则以截止时间为基准，由服务端计算提前时间。未设置时间时不能启用提醒。完整更新省略时间或提醒字段即清除对应设置。

`V72__add_personal_todo_start_at.sql` 保存开始时间；`V74__add_personal_todo_schedule_and_reminder.sql` 增加全天与提醒字段、发送标记及扫描索引。保留已发布迁移不变。

提醒任务默认每 30 秒扫描最多 100 条到期未完成事项，将提醒写入已有站内通知中心，通知只发送给事项所属员工。条件更新与通知写入在同一事务内执行，防止多个实例重复发送；写入失败回滚发送标记。修改排程后重新计算提醒时间；仅修改标题或备注且提醒时间不变时保留发送标记。通知详情的“查看待办”链接打开本人事项；删除或无权限时不展示旧数据。

前端以 Ardot `39:9`、`39:148`、`39:477` 为依据，实现今日清单、收集箱、分类、搜索、完成/重开、行内添加、编辑、确认删除、七天日历与全天区。跨天事项按每天裁切，零点结束不多占一天；重叠时间块并排，相邻独立时间块复用整列。周切换和分类搜索组合使用。业务数据不依赖浏览器本地存储。

验收：`cd hub-web && npm run test && npm run build`；`cd server && mvn -Dtest=TaskTodoBusinessRulesTest,PersonalTodoReminderTest test`。浏览器夹具用于隔离交互与截图；实际 SQL、权限和提醒事务由 H2 测试验证。
