# 原始文档内容（保留参考）

## 一、概述

### 1.1 设计目标

将 Workforce Hub 的功能模块设计为可插拔的插件，支持：
- 后端 JAR 插件热加载（基于 PF4J）
- 前端组件动态注册与渲染
- 按角色过滤功能入口
- 插件生命周期管理（安装、启用、停用、卸载）

### 1.2 插件类型

| 类型       | 说明                           | 管理端       | 员工端               |
|------------|--------------------------------|--------------|----------------------|
| UI插件     | 带前端组件，提供用户操作界面   | 显示管理入口 | 显示在工作台导航     |
| 功能插件   | 纯后端，提供API或定时任务      | 显示管理入口 | 不显示，但功能可用   |

示例：
- UI 插件：假期管理（有余额页面、请假表单）
- 功能插件：自动考勤计算（定时任务，无页面）、消息推送网关（纯 API）

## 二、插件状态机

### 2.1 状态定义

```
┌─────────┐    上传     ┌──────────┐   启用    ┌─────────┐
│  未安装 │ ──────────→ │  已安装  │ ────────→ │  运行中 │
└─────────┘             │ (未启用) │           └─────────┘
                        └──────────┘               ↑  │
                             ↑                     │  │ 停用
                             │                     │  ↓
                        ┌──────────┐           ┌─────────┐
                        │  卸载中  │ ←──────── │  已停用 │
                        └──────────┘   卸载    └─────────┘
                                                  ↑  │
                                                  │  │
                                              ┌──────────┐
                                              │  异常    │
                                              │(启动失败)│
                                              └──────────┘
```

| 状态            | 值        | 说明                 |
|-----------------|-----------|----------------------|
| NOT_INSTALLED   | -         | JAR未上传            |
| INSTALLED       | installed | JAR已上传，未启用    |
| ACTIVE          | active    | 正常运行中           |
| STOPPED         | stopped   | 手动停用             |
| ERROR           | error     | 启动失败或运行异常   |

### 2.2 状态颜色（管理端）

| 状态           | 颜色 | 图标 |
|----------------|------|------|
| 运行中         | 绿色 | ●    |
| 已停用         | 灰色 | ●    |
| 异常           | 红色 | ●    |
| 已安装(未启用) | 黄色 | ●    |

### 2.3 操作按钮映射

| 状态   | 可用操作           |
|--------|--------------------|
| 运行中 | 停用、配置、卸载   |
| 已停用 | 启用、配置、卸载   |
| 异常   | 重试、停用、卸载   |
| 已安装 | 启用、卸载         |

## 四、员工端展示

### 4.1 设计规则

- 只显示**已启用且带前端的插件**（UI 插件 + ACTIVE 状态）
- 不显示插件状态（员工不需要知道）
- 不显示功能插件（纯后端的不出现）
- 按角色过滤（员工看不到管理类插件）

### 4.2 工作台布局

### 4.3 插件归组规则

- 相同 `directory` 的插件自动归为一组
- 未匹配到已有目录的插件自动创建新分组
- 分组排序和组内排序由 `order` 字段控制

### 5.3 插件管理服务

```java
@Service
public class PluginService {
    
    private final PluginManager pluginManager;
    
    public PluginService() {
        this.pluginManager = new JarPluginManager();
        pluginManager.loadPlugins();
        pluginManager.startPlugins();
    }
    
    // 上传并安装插件
    public PluginInfo installPlugin(MultipartFile jarFile);
    
    // 卸载插件
    public void uninstallPlugin(String pluginId);
    
    // 启用/停用
    public void togglePlugin(String pluginId, boolean enable);
    
    // 获取插件列表
    public List<PluginInfo> getPlugins();
    
    // 获取某个扩展点的所有实现
    public <T extends ExtensionPoint> List<T> getExtensions(Class<T> type);
}
```

### 5.4 插件类型判断逻辑

```java
public PluginType resolvePluginType(Path jarPath) {
    PluginDescriptor descriptor = parsePluginJson(jarPath);
    
    if (descriptor.getFrontend() != null 
        && descriptor.getFrontend().getEntry() != null) {
        return PluginType.UI;           // 有前端入口 → UI 插件
    }
    return PluginType.FUNCTIONAL;       // 无前端入口 → 功能插件
}
```

## 七、数据库设计

### 7.1 插件注册表

```sql
CREATE TABLE sys_plugin (
    plugin_id VARCHAR(64) PRIMARY KEY,
    name VARCHAR(128) NOT NULL,
    description VARCHAR(512),
    version VARCHAR(32) NOT NULL,
    type VARCHAR(32) NOT NULL,           -- 'UI' 或 'FUNCTIONAL'
    status VARCHAR(32) NOT NULL DEFAULT 'INSTALLED',
    jar_path VARCHAR(512) NOT NULL,
    frontend_entry VARCHAR(512),         -- 前端 JS 入口，功能插件为空
    provider VARCHAR(128),
    error_message TEXT,
    installed_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);
```

### 7.2 插件依赖关系

```sql
CREATE TABLE sys_plugin_dependency (
    plugin_id VARCHAR(64) NOT NULL,
    depends_on VARCHAR(64) NOT NULL,
    PRIMARY KEY (plugin_id, depends_on)
);
```

### 7.3 插件配置

```sql
CREATE TABLE sys_plugin_config (
    plugin_id VARCHAR(64) NOT NULL,
    config_key VARCHAR(128) NOT NULL,
    config_value TEXT,
    PRIMARY KEY (plugin_id, config_key)
);
```

### 7.4 插件-角色映射

```sql
CREATE TABLE sys_plugin_role (
    plugin_id VARCHAR(64) NOT NULL,
```

### 11.2 启动时校验

```java
public void validateDependencies(PluginDescriptor plugin, Set<String> loadedPlugins) {
    for (String dep : plugin.getDependencies()) {
        if (!loadedPlugins.contains(dep)) {
            throw new PluginLoadException(
                "插件 [%s] 缺少必须依赖 [%s]".formatted(plugin.getId(), dep)
            );
        }
    }
}
```

### 11.3 跨插件调用

插件通过 SPI 扩展点调用其他插件的功能，共享同一个数据库和 Spring 事务管理器：

```java
public class AttendancePlugin {
    @Autowired
    private LeaveExtension leaveExtension;  // 通过 SPI 注入
    
    public void handleApproval() {
        leaveExtension.deductBalance(userId, leaveTypeId, minutes);
    }
}
```

## 十二、数据库迁移策略

### 12.1 迁移时机

| 场景                   | 是否需要迁移         |
|------------------------|----------------------|
| 首次安装插件           | 是，创建插件表       |

使用插件 ID 前缀避免冲突：

```
leave_V1__init.sql
```

```java
@Override
public void start() {

        .dataSource(dataSource)
        .locations("classpath:db/migration")
        .baselineOnMigrate(true)
        .load();
    flyway.migrate();
}
```

## 十三、开发计划（8 周）

### 可行性评估：6-7/10

首版定位为"可信、签名的内部插件平台"，不承诺第三方不可信插件隔离、完美热卸载和多节点同步。

### 阶段划分

| 阶段     | 时间     | 目标                                 | 交付物                                         |
|----------|----------|--------------------------------------|------------------------------------------------|
| 架构验证 | 第 1 周  | 验证PF4J+Spring Boot集成可行性       | plugin-sdk模块、PF4J PoC、Flyway独立history表验证 |
| 后端核心 | 第2-3周  | 插件生命周期管理、安全校验、配置持久化 | 状态机、签名校验、Flyway、配置CRUD、通用调用网关、审计日志 |
| 管理端   | 第 4 周  | 插件管理页面                         | 上传/启停/配置/卸载/错误展示/权限码            |
| 员工端   | 第 5 周  | 动态插件加载、工作台入口             | 清单API、IIFE加载器、SRI校验、动态导航         |
| 样板插件 | 第 6 周  | 验证完整链路                         | 1个UI插件+1个功能插件+SDK示例                  |
| 稳定性   | 第 7 周  | 异常恢复、边界测试                   | 重复启停、迁移失败、权限越权、CSP兼容性        |
| 验收交付 | 第 8 周  | 全量回归、文档、部署                 | 回归测试、浏览器截图、Docker部署、插件开发文档 |

### 各阶段详细内容

#### 第 1 周：架构验证

- 搭建 `plugin-sdk` 模块（SPI 接口、DTO、宿主 API 版本）
- PF4J Core 集成 PoC（加载/启停/恢复）
- 手动创建插件子 Spring Context 验证
- Flyway 独立 history 表验证

#### 第 2-3 周：后端核心

- 插件状态机持久化（安装/迁移/启用/停用/异常/需重启）
- JAR 签名校验、SHA-256、大小限制、路径校验、临时隔离区
- Flyway 由宿主执行，每个插件独立 history 表，迁移失败禁止启动
- 插件配置 CRUD
- 通用调用网关（禁止动态注册 @RestController 和 @Scheduled）
- 审计日志（上传、启停、配置变更、卸载）
- 卸载默认保留数据库数据，禁止自动回滚或删表
- 插件文件放入 `/app/storage` 持久卷，服务重启后恢复

#### 第 4 周：管理端

- 上传 JAR + 签名校验
- 插件列表（状态、版本、类型、依赖）
- 启用/停用/卸载操作
- 配置编辑界面
- 错误日志展示
- 新增 `ADMIN_PLUGIN_MANAGE` 权限码，加入 `AdminPermissionFilter`

#### 第 5 周：员工端

- 插件清单 API（后端过滤权限，当前员工无角色码，先支持"全部员工/主管/部门/岗位/指定用户"）
- IIFE 格式动态脚本加载器（同源地址、固定注册协议）
- SHA-384/SRI 校验 + CSP 配置
- 左侧导航动态渲染（按目录归组）
- 右侧内容区动态挂载

#### 第 6 周：样板插件

- 1 个 UI 插件（如"公告通知"）
- 1 个功能插件（如"考勤统计定时任务"）
- 插件 SDK 使用示例
- 插件构建脚本（Maven 后端 + Vite 前端）

#### 第 7 周：稳定性测试

- 重复启停测试
- 迁移失败恢复测试
- 权限越权测试

## 十六、风险与约束

| 风险                     | 应对方案                                                             |
|--------------------------|----------------------------------------------------------------------|
| PF4J与Spring Boot3.x兼容性 | 用PF4J Core 3.15.0，手动管理Spring子Context，不引入pf4j-spring       |
| 安全风险                 | JAR签名、SHA-256、大小限制、路径校验、临时隔离区                      |
| 前端动态加载复杂度       | IIFE格式+全局变量+SRI校验+CSP                                        |
| 跨插件事务               | 共享数据库，SPI接口调用，通用调用网关                                 |
| ClassLoader冲突          | PF4J自带隔离机制，每个插件独立ClassLoader                             |
| Flyway版本冲突           | 每个插件独立history表，迁移失败禁止启动                               |
| 员工端权限               | 后端过滤，当前无角色码，先支持"全部/主管/部门/岗位/指定用户"          |

---

## 十七、关键约束

1. **不引入 pf4j-spring**：手动管理 Spring 子 Context，避免版本冲突
2. **不升级 Spring Boot**：保持 3.2.5，用 PF4J Core 适配
3. **不迁移现有模块**：两个月内不动考勤/假期/审批，用样板插件验证平台
4. **不做第三方沙箱**：首版只支持内部可信插件
5. **禁止动态注册 @RestController**：插件 API 通过通用调用网关暴露
6. **禁止动态注册 @Scheduled**：插件定时任务由宿主管理
