## 第二部分：部署环境事实核对（关键前提）

领导审查报告大量以"分布式下失效"为前提，需先确认项目实际部署形态。

| 检查项 | 证据 | 结论 |
|--------|------|------|
| `docker-compose.yml` server 服务 | 无 `deploy.replicas`，单实例 | 单实例部署 |
| `application.yml` profile | 仅 `api`/`worker` 两 profile，同进程 | 单进程 |
| Spring Cloud / Eureka / Nacos | 未引入 | 非微服务架构 |
| MySQL / Redis | 单节点 | 非集群 |
| 反向代理 | 单 Nginx | 无负载均衡 |

**结论**：项目当前为单实例部署。领导审查报告中"分布式下无效"类指控（共 6 项：AttendanceService 单机锁、@Scheduled 重复执行、Redisson 建议、ShedLock 建议、Redisson 分布式锁建议、CAS 乐观锁建议）在当前阶段均不构成实际风险。

## 第九部分：阶段性结论

### 关于领导审查报告本身的质量

1. **后端审查报告质量较差**：42 项中 9 项不属实（含 1 项方法名编造）、6 项忽视已存在的实现（HikariCP 配置、actuator 限制、CAS 行锁、分布式锁、审计日志、DTO 校验）。报告对项目实际部署形态判断失误，导致约一半"分布式问题"指控在当前阶段不适用。
2. **admin-web 审查报告质量中等**：对 Vue 3 响应式机制有误判（`nodes.value.find(...).position` 直接赋值会触发响应式）；对 Pinia `initialized` 守卫、`keep-alive` 未使用等代码事实未核对。但中风险以下的代码风格/重复问题识别较准。
3. **employee-web 审查报告质量较高**：29 项中 24 项属实、5 项部分属实，仅 2 项不属实。与 94/95 审重叠度低，新发现真实。**建议作为 employee-web 治理的主要输入**。

### 10-1 admin-web `hasPermission` 默认拒绝（commit `f086b9c`）

**问题**：`admin-web/src/stores/session.ts:29-36` `hasPermission` 在 `permissionCodes` 缺失或为空时返回 `true`，后端漏传权限码会导致普通管理员越权访问受限菜单。


```typescript
replaceConversations(records: ConversationRecord[]) {

mergeBackendMessages(conversationId: string, backendMessages: ConversationMessage[]) {
  const conversation = this.conversations.find((item) => item.id === conversationId);
  if (!conversation || !backendMessages.length) return;
```
