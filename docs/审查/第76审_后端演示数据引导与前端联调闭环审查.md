## 第一部分：提交内容概览

本轮围绕前端联调补齐后端演示闭环。

- 新增 `GET /api/admin/leave/types`，用于后台和本地脚本复用已有假种。
- 新增 `GET /api/admin/workflow/process-types`，支持按 `processCode` 查询流程类型，避免脚本只能盲创建。
- 新增 `server/scripts/dev/bootstrap_demo_data.py`，幂等准备 demo 账号、组织关系、假期余额、流程模板、IM 私聊、请假待办、Agent ACL 和 IM-Agent 首轮回复。
- demo 余额引导改为按 `availableMinutes + frozenMinutes` 控制总额度，避免存在冻结申请时重复执行脚本把账户总额抬高。
- `ModuleLeaveApiIntegrationTest` 和 `ModuleWorkflowAdminApiIntegrationTest` 补充新增查询接口断言。
- `module-leave` 文档同步提交冻结、审批扣减、驳回/撤回释放的真实语义。
- `module-workflow` 文档同步后台流程类型查询接口和员工端联调前置。
- `docs/本地联调/employee-web后端联调基线.md` 改为一键引导脚本口径，并记录真实模型桩启动参数。
- `docs/开发规划/IMxAgent真实链路设计.md` 从“下一阶段升级到真实链路”改为当前已落地设计与剩余边界记录。
- 认证登录失败计数和邮箱验证码 Redis key 新增 `workforce.auth.redis-key-prefix`，测试环境按 `TEST_DB_NAME` 隔离，避免并行 Maven 回归互相清理。

## 第三部分：本轮新增正确性风险

| 序号 | 问题位置 | 问题描述 | 严重程度 | 优化方案 |
| --- | --- | --- | --- | --- |
| 3-1 | `bootstrap_demo_data.py` | 引导脚本通过多次 HTTP API 顺序写入组织、账号、假种、模板、IM、workflow 和 Agent 数据，不是一个数据库事务。触发条件是脚本中途失败，例如模型桩未启动或某个接口返回业务错误；失败路径是本地库会留下部分 demo 数据。当前脚本大部分步骤可重复执行，本轮也验证了重复执行可以修正余额并继续完成链路，但失败时仍需要再次运行脚本补齐。 | P2 | 保持脚本幂等，新增步骤时必须先查询再创建；对不可自动修复的半成品状态要显式报错并写入文档。 |
| 3-2 | `bootstrap_demo_data.py`、`start_agent_stub_server.py` | IM-Agent 演示依赖后端启动时打开 `AGENT_MODEL_ENABLED=true` 并指向本地 OpenAI 兼容模型桩。触发条件是后端未带这些环境变量启动；失败路径是 IM 主链路正常，但 Agent 回复任务会失败或无回复。当前联调文档已写明后端启动参数，接口验收已验证模型桩回复可见。 | P2 | 演示前把后端启动命令和模型桩纳入固定检查；后续 admin-web/运维入口补充模型失败可见性和重试处置。 |
| 3-3 | `GET /api/admin/leave/types`、`GET /api/admin/workflow/process-types` | 两个新增后台列表接口当前不分页。触发条件是生产环境流程类型或假种数量异常膨胀；失败路径是一次性返回全部记录。按业务模型这两类主数据低频低量，不影响当前演示闭环。 | P3 | admin-web 上线前如需通用主数据治理，再补分页和状态过滤；当前保持简单接口降低前端联调成本。 |

## 第七部分：阶段性结论

本轮后端已经从“接口存在”推进到“前端登录后有可见演示数据”：`demo.employee1` 能看到假期余额、我的申请、IM 私聊、Agent 会话和 Agent 回复；`demo.leader` 能看到审批待办。新增后台查询接口有真实 Controller/Service/Repository 执行入口，也有集成测试保护。

当前没有发现阻断前端演示接入的 P0/P1 问题。剩余风险主要集中在本地演示启动流程依赖多步骤、demo 脚本继续增长后的维护成本，以及未跑全量回归。
