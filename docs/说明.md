# 文档目录说明

`docs/` 根目录只保留本索引和中文分类目录，所有文档按类别归档，不再散落在根目录。

## 当前分类

- `产品与业务/` — 平台总导图、原始脑图、项目确认记录等业务总纲材料
- `架构与设计/` — 技术栈、后端骨架、核心表结构、状态机、权限矩阵、接口与事件清单
  - `架构图/` — 架构图、数据流图、工作流图、状态图、时序图的 JSON/HTML/PNG/SVG 产物
- `开发规划/` — 开发流程总览、开发落地清单、后续计划、队友速通指南等推进型文档
- `接口与测试/` — 按模块拆分的接口文档与测试用例（认证/组织/文件/审批/假期/考勤/会话/智能体）
- `开发日志/` — 按模块或主题记录真实开发过程
- `本地联调/` — 前后端联调基线与卡片语义、接口契约
- `审查/` — 按审查轮次归档审查结论
- `人工智能生成内容审查/` — AI 生成代码特征的抽样审查报告
- `插件化工作台/` — 插件化工作台的架构、契约、规范与验收（`归档/` 存放废弃版本）
- `安全设计/` — 全站跨站请求伪造防护设计与实施计划
- `论文/` — 论文选题材料、参考文献、配图与实验报告册
- `毕业设计/` — 毕业设计任务书等材料
- `申报材料/` — 比赛、申报、展示类材料与配图
- `部署与交付/` — Docker Compose、Nginx、部署初始化说明

## 命名与版本约定

- 目录与文件名统一使用中文，产品名、中间件名与提交号（WorkforceHub、hub-web、Flyway、35effd3 等）保留原文
- 同类型文件存在多版本时，文件名前加 `主版本.次版本.修订号`，如 `1.0.0系统架构图.html`、`1.1.0请假审批数据流图.json`
- 接口文档命名 `接口文档_<模块><主题>.md`，测试用例命名 `接口测试用例_<模块><主题>.md`
- 审查文件命名 `第N审_<主题>.md`，开发日志按模块或主题命名
- 新增文档先归入对应分类目录，新分类先建子目录再放文件；`docs/` 根目录不再新增散落文件
