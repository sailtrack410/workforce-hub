# 文件存储与云空间设计

## 一、设计目标

文件中心是消息附件、个人文件、群文件、审批附件、知识库原文件、Agent 临时产物的共同底座。第一版目标不是做完整网盘，而是先把以下问题定清楚：

- 文件真实存在哪里
- 同一文件多次发送如何去重
- 文件名、业务引用和物理对象如何分离
- 个人云空间、群空间、知识空间如何计量
- 总容量不足时如何保护系统
- 回收站、临时缓存和下载包如何清理
- Agent 为什么能读某个文件、能读到什么范围

核心原则：

- 物理存储统一，业务权限分离
- 文件名不参与物理去重，文件内容参与去重
- 配额是逻辑上限，不等于提前占用磁盘
- Agent 只能按授权上下文读取文件
- 删除、恢复、清理、下载都必须可审计

---

## 二、第一版存储形态

第一版支持两类存储 Provider：

| Provider | 用途 | 适用场景 | 说明 |
| --- | --- | --- | --- |
| `LOCAL` | 本地磁盘 | 本机开发、小规模内网试用 | 实现简单，但不适合作为长期主存储 |
| `MINIO` | 对象存储 | 私有化部署默认方案 | 推荐第一版正式部署使用 |

后续可扩展：

| Provider | 用途 | 说明 |
| --- | --- | --- |
| `OSS` | 阿里云 OSS | 公有云或混合云部署 |
| `COS` | 腾讯云 COS | 公有云或混合云部署 |
| `S3` | AWS S3 / S3 兼容存储 | 跨云兼容 |
| `WEBDAV` | 外部 WebDAV 网盘 | 可做扩展存储或归档，不建议作为高并发主存储 |

推荐私有化部署结构：

```text
公司服务器
- workforce-hub 后端服务
- MySQL
- Redis
- MinIO
  - bucket: workforce-hub
  - volume: /data/workforce-hub/minio
```

不建议把用户上传文件存放在项目目录，也不建议把文件二进制写入 MySQL。

## 三、物理文件与业务引用

文件中心要分清两个概念：

- `sys_file_object`：物理文件对象，描述“这个二进制文件存在哪里”
- `sys_attachment_ref`：业务引用，描述“这个文件在某个业务场景里叫什么、属于谁、谁能看”

示例：

```text
同一个 PDF 内容：
- 在私聊里叫 请假证明.pdf
- 在群里叫 病假材料.pdf
- 在个人文件里叫 医院证明.pdf

底层只需要一条 sys_file_object。
每次发送或保存都新增一条 sys_attachment_ref。
```

文件名只影响展示，不影响物理去重。

### 3.1 推荐字段补充

当前已有 `file_hash`，后续落地时建议拆细：

```text
sys_file_object
- id

- object_key

- content_sha256
- mime_type
- file_ext

```

```text

```

## 四、文件去重规则

第一版按二进制内容去重：

```text
去重键 = content_sha256 + file_size
```

MD5 可以保留用于兼容或快速校验，但不作为主唯一依据。原因是 MD5 有碰撞风险，文件中心属于平台底座，主校验建议直接使用 SHA-256。

上传流程：

1. 客户端上传前计算 `sha256 + file_size`，向后端询问是否已存在。
2. 如果命中已存在文件，后端不要求重复上传，直接创建业务引用，实现秒传。
3. 如果未命中，后端创建上传票据。
4. 客户端上传到 `LOCAL` 或 `MINIO`。
5. 上传完成后调用确认接口。
6. 服务端重新计算 `sha256 + file_size`，不能只信客户端。
7. 服务端创建或复用 `sys_file_object`，再创建 `sys_attachment_ref`。

注意：

- 文件重命名不会改变 hash。
- Word、PDF 等文件重新另存为后可能写入内部元数据，二进制 hash 会变化。
- 第一版不做“视觉内容相同”的高级去重，只做二进制去重。

## 五、云空间与配额

### 5.1 配额分层

第一版建议支持三层逻辑配额：

| 配额类型 | 含义 | 示例 |
| --- | --- | --- |
| 个人默认配额 | 每个员工默认可用空间 | 10GB |
| 空间级配额 | 群、知识库、部门等空间上限 | 群文件 50GB，知识库 200GB |
| 组织总池配额 | 全系统长期文件总上限 | 400GB |

个人配额支持覆盖：

```text
个人覆盖 > 部门/角色策略 > 系统默认
```

例如：

- 系统默认每人 10GB
- 设计部默认每人 50GB
- 张三单独设置 100GB

### 5.2 逻辑配额与物理容量

如果 100 人团队每人默认 10GB，逻辑总额是 1TB。但如果服务器只有 500GB，这不是问题，因为配额不会提前占用磁盘。

只有真实上传文件才占用物理空间。

因此必须同时控制：

```text
能否上传 = 个人未超额 && 所属空间未超额 && 组织总池未超额 && 存储后端真实容量安全
```

示例：

```text
服务器磁盘：500GB
长期文件池上限：400GB
临时缓存池上限：50GB
系统安全预留：50GB
```

阈值策略：

| 阈值 | 处理 |
| --- | --- |
| 长期文件池 80% | 管理员预警 |
| 长期文件池 90% | 强预警，可限制大文件上传 |
| 长期文件池 100% | 阻断新增长期文件上传 |
| 临时缓存池 80% | 自动清理过期缓存 |
| 临时缓存池 100% | 阻断批量下载、预览转码、Agent 临时文件生成 |
| 系统磁盘低于安全预留 | 进入写入保护，只允许删除、清理、扩容相关操作 |

### 5.3 占用归属

| 文件类型 | 建议占用归属 |
| --- | --- |
| 个人文件 | 个人云空间 |
| 私聊附件 | 发送者附件空间，或消息附件空间策略 |
| 群文件 | 群空间 |
| 知识库文件 | 知识空间 |
| 审批附件 | 业务附件空间，不默认占个人云盘 |
| Agent 生成文件 | 默认临时空间，用户保存后再计入个人/群/知识空间 |

为了用户理解清楚，前端最好同时展示：

```text
我的空间：3.2GB / 10GB
企业总空间：368GB / 400GB
```

## 六、长期文件池与临时缓存池

长期文件池：

- 个人文件
- 群文件
- 知识库文件
- 审批附件
- 消息附件

临时缓存池：

- 上传分片临时文件
- 批量下载 ZIP
- 文件预览转码缓存
- Agent 临时生成文件
- 临时导出报表

消息附件不建议当缓存处理。只要用户后续需要回看、下载，就应该算长期文件。

临时缓存默认保留建议：

| 类型 | 默认保留 |
| --- | --- |
| 上传票据未确认对象 | 24 小时 |
| 批量下载 ZIP | 7 天 |
| 预览转码缓存 | 7-30 天 |
| Agent 临时生成文件 | 7 天 |
| 临时导出报表 | 7 天 |

## 七、下载与预签名链接

下载不应该直接暴露真实对象存储地址。建议流程：

1. 用户请求下载某个业务文件引用。
2. 后端校验 `sys_attachment_ref` 权限。
3. 后端创建 `sys_download_ticket`。
4. 返回短期有效下载链接或重定向到短期预签名 URL。
5. 下载行为写入访问日志。

建议默认值：

| 项目 | 默认值 |
| --- | --- |
| 单文件下载链接有效期 | 5-10 分钟 |
| 批量下载 ZIP 保留期 | 7 天 |
| 下载失败重试窗口 | 下载链接有效期内 |

下载链接过期不代表文件删除，只是需要重新申请下载票据。

## 八、回收站与删除

回收站不难做，但必须明确“删除的是业务引用，不一定马上删除物理文件”。

### 8.1 删除分层

| 删除层级 | 含义 |
| --- | --- |
| 删除业务引用 | 用户删除个人文件、群文件、消息附件引用 |
| 进入回收站 | 引用标记 `deleted_at`，保留可恢复窗口 |
| 彻底删除引用 | 回收站到期或用户手动彻底删除 |
| 清理物理对象 | 当没有任何引用指向物理文件后，再按无引用清理策略删除 |

### 8.2 默认规则

| 类型 | 默认规则 |
| --- | --- |
| 个人文件回收站 | 30 天 |
| 群文件回收站 | 30 天，群主/管理员可恢复 |
| 知识库文件删除 | 建议先停用或归档，管理员确认后删除 |
| 审批附件删除 | 默认不允许普通用户删除，按业务归档周期处理 |
| 消息附件删除 | 删除消息引用不一定删除物理对象 |
| 无引用物理文件 | 7 天后清理 |

### 8.3 回收站权限

| 场景 | 恢复权限 |
| --- | --- |
| 个人文件 | 文件所有者 |
| 群文件 | 上传者、群主、群管理员 |
| 知识库文件 | 知识库管理员 |
| 审批附件 | 流程管理员或系统归档任务 |

回收站建议占用空间，直到彻底清理。否则用户删除大量文件后立刻释放空间，随后又恢复，会导致配额统计难以解释。

## 九、Agent 与文件联动

Agent 不直接按 `sys_file_object` 读取文件，而是通过业务授权上下文读取。

授权来源：

| 授权来源 | 含义 |
| --- | --- |
| `OWNER_REQUEST` | 文件所有者主动让 Agent 处理 |
| `CONVERSATION_CONTEXT` | 私聊参与者在当前会话中触发 |
| `GROUP_CONTEXT` | 群成员在群内触发，受群策略限制 |
| `WORKFLOW_ATTACHMENT` | 审批附件，Agent 作为预审节点读取 |
| `KB_BINDING` | 文件已进入知识库，Agent 通过知识空间检索 |

第一版建议支持的 Agent 文件能力：

- 文件总结
- 单文件问答
- 群文件问答
- 审批附件预审
- 知识库入库建议
- Agent 生成报告临时下载

Agent 产物处理：

| Agent 产物 | 默认处理 |
| --- | --- |
| 文件总结文本 | 存 Agent 任务结果，不占云盘 |
| 生成的报告/表格 | 临时文件，默认 7 天 |
| 用户保存到我的文件 | 计入个人云空间 |
| 群主保存到群文件 | 计入群空间 |
| 管理员沉淀到知识库 | 计入知识空间 |

所有 Agent 文件读取、总结、预审、生成行为都必须写审计日志。

## 十、安全与治理补充

文件中心后续还需要考虑以下点：

### 1. 文件类型与大小限制

- 按场景配置允许上传的扩展名、MIME 类型和最大大小。
- 例如头像、审批附件、知识库文档、群文件使用不同限制。

### 2. 防病毒与内容安全

- 第一版可预留 `scan_status`。
- 未扫描或扫描失败的文件不进入知识库，不允许 Agent 读取。
- 后续可接 ClamAV 或企业杀毒网关。

### 3. 预览与转码

- Office、PDF、图片、视频预览建议走异步转码。
- 转码结果放临时缓存池。
- 转码失败不影响原文件下载。

### 4. 敏感文件与水印

- 可按文件归属或知识空间配置下载水印。
- 管理员审计下载敏感文件时记录访问原因。

### 5. 外部存储迁移

- `storage_provider + bucket_name + object_key` 能支持从 `LOCAL` 迁移到 `MINIO`，或从 `MINIO` 迁移到 `OSS/S3`。
- 迁移时不改变业务引用，只更新物理对象定位。

### 6. 并发与幂等

- 上传确认接口必须幂等。
- 同一 `sha256 + file_size` 并发上传时，只能生成一条最终物理对象记录。

### 7. 审计

建议记录：

- 上传
- 下载
- 预览
- 删除
- 恢复
- 彻底删除
- Agent 读取
- 知识库入库
- 外部分享或导出

## 十二、第一版边界

第一版支持：

- `LOCAL` 与 `MINIO`
- 两段式上传
- 二进制内容去重
- 个人默认配额
- 个人单独配额覆盖
- 组织总池配额
- 长期文件池与临时缓存池阈值
- 下载短期票据
- 回收站 30 天
- 无引用物理文件延迟清理
- Agent 按授权上下文读取文件

第一版暂不支持：

- 视觉内容相同的高级去重
- 多存储自动冷热分层
- 多副本跨区域容灾
- 公网匿名永久分享
- WebDAV 作为高并发主存储
- Agent 无授权读取私聊、群聊、个人文件
